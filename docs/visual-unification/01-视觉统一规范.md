# SCM 看板 · 视觉统一规范（v0.3）

> 目的：把「卡片骨架」「预警/状态语义色」「强调色」「数字排版」四件事各收敛成**唯一一套**，
> 消除「同一页三种卡片、同一种颜色多种含义」的散乱。
>
> 本文件是**施工依据**，改代码前先读这里；改了要回来更新版本号。
>
> v0.2 新增：§8「全站统一清单（带优先级）」—— 把散落在各页面的不一致点逐一列全。

---

## 0. 一句话总纲

**颜色只表达「状态」，不表达「好看」；卡片只保留「一种骨架」；强调色只留「一个」。**

---

## 1. 现状病灶（为什么要做）

| 位置 | 现在的画法 | 问题 |
|---|---|---|
| Dashboard 顶部 5 卡 | `<Card>` + 右上角**彩色图标块**（emerald/red/sky…） | 每张卡一个装饰色，第五张 sky 与状态语义无关 |
| 供需管理 RiskOverview 4 卡（KpiCard） | `<Card>` + **数字本身变色**（rose/amber/emerald） | 和 Dashboard「图标块变色」是两套表达 |
| 供需管理 ProjectCard | 手写 `<button>` + `rounded-lg border`，非 `<Card>` 组件 | 圆角/边框/结构与别处完全不同 |
| 供需管理 AnalysisSection | `<Card>` + 自绘 `border-b` 标题栏 | 又一种「带标题栏」画法 |
| 库存 DohBucketCards | `<Card>` + 顶部 3px 色条 + 大数字变色 + 图标块 | 第四套「预警卡」画法 |
| 库存 OrderTimingBar | 手写 `rounded-lg border bg-card` | 非 Card 组件 |

**根因**：三套语义混在一个维度 —— ① 状态语义（必须保留）② 装饰强调（该统一）③ 图表分类色（该固定）。
红/黄/绿/蓝/sky/emerald 被同时用于三者，导致「预警红」和「装饰红」打架。

---

## 2. 卡片骨架（唯一一种）

全站所有「信息卡」统一用 `<Card>` 组件 + 以下三段式结构：

```
┌─────────────────────────────────────────┐
│ 标题行：  [左] 标题(+可选一句话结论)   [右] 角标/action/图标 │  ← 统一 height、统一 text-sm font-medium
│ ─────────────────────────────────────── │  ← 只在「需要分区」时画 1px 分隔线（border-b），不要每个卡都画
│ 内容区：  图表 / 表格 / 数字 / 空态      │
└─────────────────────────────────────────┘
```

**硬规则：**

1. **标题下必带一句「由数据算出的人话结论」**（已有铁律，升级为全站卡片通用骨架）。
2. **不再手写卡片**：ProjectCard、AnalysisSection、OrderTimingBar、KpiCard 全部改回用 `<Card>`，
   圆角统一走 `--radius`，边框统一走 `ring-1 ring-foreground/10`（Card 组件已内置）。
3. **指标卡的「状态」表达二选一，只保留一种**（见 §4 决定）：数字颜色 or 左侧/顶部色条。
   不能有的卡变色、有的卡变图标块、有的卡加色条。

## 3. 语义色规范（唯一映射表）

颜色分三组，**互不混用**：

### 3.1 预警 / 状态语义色（业务含义，必须保留、全站唯一）

| 语义 | 色名 | 亮色 | 暗色 | 用途 |
|---|---|---|---|---|
| 危险 / 超期 / 断货 / 独供风险 | `red` | `#dc2626`（red-600） | red-400 | 超期、库存耗尽、高风险 |
| 警告 / 临期 / 紧张 / 偏低 | `amber` | `#d97706`（amber-600） | amber-400 | 临期、DOH偏低、产能紧张 |
| 正常 / 充足 / 无风险 | `emerald` | `#059669`（emerald-600） | emerald-400 | 正常、充足、OK |
| 未评估 / 无数据 / 禁用 | `muted` | 灰 | 灰 | 无法评估、未知、不可用 |

> **A 股语境说明**：涨跌的红/绿是**另一套语义**（金融方向约定），与这里的「预警红绿」不是一回事。
> 当前看板暂无行情涨跌展示，若未来引入，需用**图标 + 前缀符号**区分，不得复用 §3.1 的纯色。

### 3.2 强调色（只留一个）

| 用途 | 色 | 说明 |
|---|---|---|
| 可点击 / 选中 / 当前 / 主按钮 | `primary`（当前是近黑 `oklch(0.205)`） | 全站唯一强调色 |
| 链接 / 图表主系列 | 同 `primary` 或固定主色 | 不再用 sky 当装饰 |

> **删除**：`bg-sky-500/10`、`bg-emerald-500/10`（当装饰用的那批）等「第五种颜色」。
> sky/emerald 只允许以 §3.1 的「状态语义」身份出现，不允许作为「这个图标好看」的装饰。

### 3.3 图表分类色板（固定一张，全站复用）

当前 `LINE_COLORS`（DemandLineChart.tsx）已是一张 10 色分类板，作为**全站唯一**图表分类色板，
折线/柱状/饼图/热力图都从它取色，禁止各图表另起炉灶。

## 4. 需要拍板的一个关键决策

Dashboard「图标块变色」vs 供需 KpiCard「数字变色」vs 库存「色条+变色」，三者要收敛成一个。
**推荐方案：保留「顶部/左侧 3px 色条 + 图标」表达状态，数字统一深色（`text-foreground`），
状态色只出现在色条与图标上。** 理由：

- 数字保持深色，`tabular-nums` 对齐最清晰，扫读快；
- 色条 + 图标是「双重编码」，色觉障碍用户也能识别（现有 DohBucketCards 已这么做了，且加了注释）；
- 避免「满屏彩色数字」导致的视觉噪音。

## 5. 数字排版（唯一规则）

| 元素 | 规格 |
|---|---|
| 大数字（KPI 主值） | `text-2xl font-semibold tracking-tight tabular-nums`，颜色 `text-foreground` |
| 指标标签 | `text-xs text-muted-foreground` |
| 一句话结论 / hint | `text-xs text-muted-foreground`，有危险时 `text-red-600`，有警告时 `text-amber-600` |
| 一个值 → 文字；有结构 → 图表（已有铁律） | 继续遵守 |

### 5.1 统计卡状态表达规格（v0.3 定稿，全站唯一）

> 背景：曾同时存在两套语言 —— 库存/份额卡「整卡铺底色 + 数字变色」（重编码），
> 供需/Dashboard/变更卡「白底 + 顶部色条 + 深色数字」（轻编码）。v0.3 起全站**只允许轻编码**。

所有统计卡 / 预警指标卡 = 以下五件套，缺一不可、多一不可：

| 元素 | 规格 | 说明 |
|---|---|---|
| 卡片底 | 白底（`bg-card`） | **禁止整卡铺状态底色**（如 `bg-red-50`） |
| 状态强色 | 顶部 3px 色条 `absolute inset-x-0 top-0 h-[3px]` | 全卡唯一的饱和色来源 |
| 图标块 | 右侧 `h-8 w-8 rounded-lg`，`*-500/10` 底 + `*-600` 字 | 浅底，禁止深色实底（如 `bg-red-700 text-white`） |
| 数字 | §5 规格（`text-2xl` 深色） | **禁止数字变色** |
| 选中态 | `ring-2 ring-primary ring-offset-1` | 可点选过滤的卡统一 |

**大字截断铁律**：`value` 只放短值（数字 / 月份 / 百分比）；长标识（料号、名称）一律下沉到 hint（hint 有 `truncate` + `title` 兜底）。反例：「1月 · 110205-00032」挤爆 text-2xl。

已覆盖（v1.4）：库存 `DohBucketCards`（去掉 cardCls 整卡底色 / textCls 变色数字 / 深色实底图标块）、份额 `SharePage KpiCard`、供需 `KpiCard`、Dashboard 5 卡、变更 `StatTile` 5 卡。
`INV_DOH_BUCKET_META.textCls` 字段保留——它还被 `InventoryRow` 的 DOH 迷你趋势线当**线条色**用（图表用途，非数字变色）。

> 例外（有意分层，非遗漏）：变更 `ProjectChangeCard` 项目卡墙用**边框信号**（红边=超期/黄边=临期）+ 内部角标，
> 因为它的场景是「扫一眼哪个项目出事」，加色条是双重信号。指标卡=色条，内容卡墙=边框。

## 8. 全站统一清单（带优先级，2026-10-15 盘点）

> 按「影响面 × 落地难度」排序。P0 = 最该先做、收益最大；P2 = 锦上添花。

### 8.1 卡片骨架（当前有 6 种画法 → 收敛成 1 种）

| # | 位置 | 现状 | 该改成 |
|---|---|---|---|
| P0-1 | 供需 `KpiCard` | 数字变色(rose/amber/emerald) | 顶部色条 + 数字深色（见 §4） |
| P0-2 | 供需 `ProjectCard` | 手写 `<button>` + `rounded-lg` | 改用 `<Card>`，圆角走 `--radius` |
| P0-3 | 供需 `AnalysisSection` | `<Card>` + 自绘 `border-b` 标题栏 | 保留结构，但圆角/内边距对齐统一骨架 |
| P0-4 | Dashboard 5 卡 | 右上角彩色图标块(emerald/red/**sky**) | 图标块只留「状态色」，删除 sky 装饰；或改色条 |
| P1-5 | 库存 `OrderTimingBar` | 手写 `rounded-lg border bg-card` | 改用 `<Card>` |
| P1-6 | 变更 `ProjectChangeCard` | 手写 `rounded-xl border bg-card` | 改用 `<Card>`（或至少统一圆角/边框） |
| P1-7 | `MaterialSupplyCharts` 容器 | `rounded-md border bg-card` | 圆角统一走 `--radius` |

### 8.2 状态徽章（当前有 3 套「浅底+深字」画法 → 收敛）

现在「状态 chip」散落在三处，写法各不同：

1. `Badge` 组件的 `success/warning` 变体（`bg-emerald-100 text-emerald-700`）
2. 各模块 META 里的 `chipCls`（`bg-red-500/10 text-red-600`，用的 500/10 透明度）
3. 手写内联 `<span class="rounded bg-red-500/15 ...">`（用 500/15）

**统一规则**：所有「状态徽章」一律走 `Badge` 组件 + 固定三个变体
（danger / warn / ok），色值统一为 `*-500/10 底 + *-600 字`。删除手写 span。

### 8.3 语义色（红/黄/绿/蓝/橙 的「含义」必须唯一）

| 颜色 | 唯一含义 | 现在被误用的地方 |
|---|---|---|
| 红 `red` | 危险 / 超期 / 断货 / 独供 | ✅ 各 META 已正确；⚠️ Dashboard「重点物料独供」卡图标也红，语义一致可保留 |
| 琥珀 `amber` | 警告 / 临期 / 偏低 / 紧张 | ✅ 一致 |
| 绿 `emerald` | 正常 / 充足 / 完成 | ✅ 一致 |
| 蓝 `blue` | 变更「进行中」状态（`CHANGE_STATUS_META` 与 `TASK_STATE_META.todo` 用 blue） | ⚠️ 与「图表分类色」的 blue 撞了，见 §8.5 |
| 橙 `orange` | 变更「迟交完成」（late） | ⚠️ 与库存 OrderTimingBar 的「7天内」orange 撞了 |
| **天蓝 `sky`** | **无业务含义，纯装饰** | ❌ **删除**。Dashboard 卡 5「变更进行中」图标用了 sky，应改回主色/状态色 |

### 8.4 强调色（只留一个）

当前 `primary` 是近黑。全站「可点击 / 选中 / 当前」统一用它，不再出现
`bg-sky-500/10`、`text-sky-600` 等第五种强调色。选中态统一 `ring-1 ring-primary`。

### 8.5 图表分类色板（当前有 3 张，各自为政 → 收敛成 1 张）

现在有**三张**互不相干的分类色板：

| 色板 | 定义位置 | 现状 |
|---|---|---|
| `LINE_COLORS`（10 色） | `DemandLineChart.tsx` | 蓝/绿/琥珀/红/紫/青/粉/黄绿/橙/青绿 |
| `DEMAND_COLORS` / `CAPACITY_COLORS`（10 色） | `MaterialSupplyCharts.tsx` | 又一套，绿调为主 |
| `CATEGORY_PALETTE`（8 色） | `types/change.ts` | 蓝/紫/绿/橙/粉/琥珀…，**刻意避红黄绿**（这条是对的） |

**统一规则**：抽一张全站唯一的 `CHART_PALETTE` 到共享层（如 `lib/chart-palette.ts`），
三处都从它取色。**关键约束**：分类色板必须避开红/黄/绿（那是状态语义），
`CATEGORY_PALETTE` 的思路是对的，把它定为基准，其余两张向它靠拢。

### 8.6 数字排版（已有约定，列全以防遗漏）

| 元素 | 唯一规格 |
|---|---|
| KPI 主值 | `text-2xl font-semibold tracking-tight tabular-nums text-foreground` |
| 指标标签 | `text-xs text-muted-foreground` |
| 一句话结论 / hint | `text-xs text-muted-foreground`，危险 `text-red-600`、警告 `text-amber-600` |
| 卡片标题 | `text-sm font-medium`（全站统一，现有 h2 已是） |
| 页头标题 | `text-4xl font-semibold tracking-tight`（Dashboard/供需一致）vs 库存 `text-xl` ⚠️ 待对齐 |

### 8.7 圆角（全站统一走 `--radius`，当前有 4 个手写值）

当前散落 `rounded-lg` / `rounded-md` / `rounded-xl` / `rounded-2xl` 多种。
统一规则：**卡片/弹窗走 `--radius`（默认 0.625rem，即 rounded-lg 级别）**，
`rounded-md` 仅用于卡片内的小元素（按钮/输入/色块），不再手写 `rounded-xl/2xl`。
`Card` 组件已内置 `rounded-xl`（=`--radius` + 4px 的映射），其余手写卡片要改回 `<Card>`。

### 8.8 页头标题（两套字号）

- Dashboard / 供需管理：`text-4xl font-semibold tracking-tight`
- 库存 / 供应商 / 份额 / 变更：`text-xl` 或 `text-2xl`

**统一**：全站页头标题定为**一套**（建议 `text-2xl font-semibold tracking-tight`，
`text-4xl` 太大，看板页头不需要那么夸张）。
