## 2 后端

### 2.1 新建 `backend/app/scoring.py`（纯函数，不碰 DB）

放这里而不是塞进 router，是为了 `scripts/verify_segments.py` 能直接 import 断言，不需要起服务。

```python
TIERS = (0, 0.3, 0.5, 0.7, 1)                   # 只认这五个值
score(tiers: dict, weights: dict, card: str | None = None, threshold=50) -> Result
    # 返回 cap/will/filled_cap/filled_will/quadrant/card
```

全部计算只有三步，没有归一化公式：

```python
if card in ("red", "yellow"):                   # 牌一打，两维归零，短路
    return Result(cap=0.0, will=0.0, quadrant="exit", card=card, ...)
分 = round(Σ(wᵢ × tierᵢ × 100) / Σ(wᵢ), 1)     # 只对非 None 的项求和
象限 = "partner" if cap > 50 and will > 50 else ...
```

`TIERS` 是唯一允许的取值集合，入参不在集合内直接抛错。

`score()` 的硬规则：

1. **牌优先**：`card` 非空 → 直接返回 0/0/exit，不看档位、不看缺失。
2. 单项为 `None` → 不进加权。
3. 分母 = 已填项权重和，不是固定 1。
4. 有效项 ≤ 3 → 该维 `None`，`quadrant = "incomplete"`。
5. 象限判定 **严格大于**：`cap > 50 and will > 50`，正好 50 不算过关。
6. `filled_cap / filled_will` 按**实际填写数**记，与牌无关（复盘要看「他填了几项」）。
7. 返回 `formula_version = "v1"`。

两张表，追加在 `ChangeArchive` 之后：

class SupplierSegment(Base):

### 2.3 `backend/app/schemas.py`

- 常量区新增：`SEGMENT_THRESHOLD = 50`、`SEGMENT_WEIGHTS`（见方案 §7）、`SEGMENT_TIERS = (0, 0.3, 0.5, 0.7, 1)`。

- 校验：

  - 12 个档位值必须 ∈ `SEGMENT_TIERS`，其他值（`2.5`、`0.8`、`100`）一律 422

  - 权重 JSON 两组各自合计必须 = 100（容差 0.01）

### 2.4 新建 `backend/app/routers/segments.py`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/supplier-segments` | 过滤：`period`（默认最新月）、`segment`、`q` |
| GET | `/api/supplier-segments/summary` | 各象限家数 / 完整率 / 未评级数 |
| GET | `/api/supplier-segments/periods` | 月份倒序列表 |
| POST | `/api/supplier-segments` | upsert（同 period+PN+供应商覆盖） |
| PUT / DELETE | `/api/supplier-segments/{id}` | |
| GET | `/api/supplier-segments/prefill` | `?period=&material_code=&supplier_code=` 返上期 12 项 |
| POST | `/api/supplier-segments/copy-period` | `?from=&to=` 整批复制，返回条数，`to` 已有记录跳过 |
| GET / PUT | `/api/supplier-segment-config` | 阈值 / 权重 |
| GET | `/api/supplier-cards` | `?supplier_id=&active=` 牌列表 |
| POST | `/api/supplier-cards` | 打牌；已有生效牌则旧牌 `effective_to` 置今日 |
| PUT | `/api/supplier-cards/{id}/release` | 解牌，写 `effective_to` + `release_reason` |

**配置零 seed**：`main.py` 的 lifespan 只做 `create_all`，不插默认行（项目纪律：不写 seed）。`GET config` 读不到时直接返回代码里的默认值，第一次 `PUT` 才落库。

写入时同步算分并快照 `weight_snapshot`，不存「事后实时算」——否则改权重会把历史结论一起改掉。

**打牌/解牌后回写评价行**：按牌生效区间重算该供应商对应月份的评价。命中期内 → `cap = will = 0`、`quadrant = "exit"`、`card_snapshot` 记牌色；过期月份重算时按原档位恢复分数。**只重算区间内的月份**，别全量重算（解牌不该抹掉历史月份的 0 分记录）。

### 3.1 四象限图实现要点

- `xAxis type="value" min=0 max=100`，`yAxis` 同；轴名「能力」「意愿」。
- 十字线用 `series.markLine`，`x: 50` / `y: 50`，虚线，`silent: true`。
- 四象限底色用 `markArea`，淡色，`z: 0`；象限名用 `markArea.label`。
- `symbolSize` 按份额映射 8–24px；无份额等大 10px。**份额取 `share_records` 最近一个月，跨项目取均值**。
- 颜色按 `quadrant`，未评级点 `emptyCircle` + 灰边。
- **牌点单独一个 series**，固定画在原点（0,0）。多个供应商同时打牌会完全重叠 → 按数量放大半径、中心显示数字，点击弹出该堆的列表。**不要给牌点加随机偏移**：坐标会变成 0.8 这种假数，老板一眼看出不对。
- 牌点不标文字标签（会叠在原点糊成一团），靠中心数字 + tooltip。
- 标签只标两类：`exit` 象限（无牌）、独供。全标会糊。
- `tooltip` 显示：供应商 / PN / 两维分 / 12 项档位 / 当前牌。
- 无任何数据 → 整卡 `EmptyState`，不放空白坐标系。

### 3.2 统计卡（4 张）

参评条目数 · 战略伙伴数 · 观察退出数 · 未评级（待补录）数

不写「双低独供数」：独供判定要跨项目，P0 不做，避免出个算不准的数。

## 5 验证

### 5.1 `scripts/verify_segments.py`（免污染，拷 backend 到临时目录跑）

断言 12 条：

1. 六项全 `1.0` → `cap == 100`；六项全 `0` → `cap == 0`
2. 六项全 `0.5` → `cap == 50`，且 `cap > 50` 为假 → 落 `exit`（全中性不算过关）
3. 业务权重下 A1 打 0、其余 5 项全 1.0 → `cap == 75.0`，**无牌时落 `partner`**
4. 同上数据 + `card="red"` → `cap == 0`、`will == 0`、`quadrant == "exit"`，且**档位入参未被修改**（原值还在）
5. `card="yellow"` → 同样 0/0/exit，`card` 字段不同，`filled_*` 仍按实际填写数
6. 解牌后重算同一行 → 分数回到 `75.0`、象限回 `partner`（验证牌不是数据覆盖）
7. 缺 2 项时按已填权重重归一 —— 结果**不等于**把缺失当 0 分算出来的值
8. 只填 3 项 → `quadrant == "incomplete"`，且不出分；但**牌生效时优先出 exit**，不进 incomplete
9. 边界：`cap=50.0, will=60` → `exit`；`cap=50.5, will=60` → `nurture`
10. `tier=0.8` / `tier=2.5` → 抛错，不入库
11. 打红牌后只重算生效月区间内的行；解牌后历史月份仍保留 0 分与 `card_snapshot="red"`
12. 权重组合计 = 99 → 422；权重快照落库后与当时配置一致

## 7 已知风险

| 风险 | 处理 |
|---|---|
| 月度录入量大（50 PN × 3 家 = 150 条/月） | 靠「Excel 导入」为主、「复制上期」补录；月度只改变化项 |
| 业务权重把结论带偏 | 配置留 `preset=equal` 开关，切换后对比象限分布 |
| 阈值 50 会让「战略伙伴」变多 | 第一版数据出来看分布，配置项改一个数字即可 |
| 主观打分光环效应（一人一下午打完 12 项，全给 0.7） | 12 项各带独立行为锚点（方案 §2）；两人分别打、取均值（P1 再看）；本期先记录 `evaluator` 留痕 |
| 5 档太粗，供应商之间并列多 | 加权后仍是连续分，图上按分数排；并列不影响象限判定，只影响排序 |
