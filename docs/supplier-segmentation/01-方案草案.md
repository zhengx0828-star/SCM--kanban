# 供应商细分 · 方案草案

模块位置：左侧导航「变更管理」下方，路由 `/segments`。
一句话：把「重点物料 × 供应商」按**能力**和**意愿**两维打分，落到四象限，回答「这家该加份额、该找替代、还是该辅导」。

---

## 1 评价单元

| 项 | 定 |
|---|---|
| 一行记录 | 期间 × 物料 PN × 供应商 |
| 期间粒度 | **月度**（`2026-10`），复用份额模块的 `MONTH_PATTERN` |
| 带不带项目 | **不带** |
| 评价范围 | 只评指定重点物料；不自动铺全库 |

**月度录入口径**：以「复制上期 + 只改变化项」为主，不做全量重填。主观 6 项月度波动大，单月结论噪声高 —— 主图默认看当月，另给「近 3 个月滚动均值」切换，两者共用同一套阈值，不平滑数据本身。

**为什么不带项目**：

1. 12 项里 9 项是供应商的客观属性（质量、交付、合格率、稽查、态度、产能弹性），不因项目改变。
2. 带项目会让同一供应商同一 PN 在两个项目出现两个互相矛盾的分数，象限图上点位重复且打架。
3. 项目只做**筛选入口**：选项目 → 取该项目在供的物料 → 看这些物料的供应商落点。

**唯一的项目级数据是「成本」**（单价存在 `project_supply_relations.unit_price`）。处理：价格指数以「同 PN 参与评价的供应商中的最低单价」为基准 1.00，供应商单价取该项目下的值；不选项目时取其所有项目单价的均值。多项目差价大时在明细里标注。

## 2 十二项口径总表

**12 项统一用同一把尺：五档 `1 / 0.7 / 0.5 / 0.3 / 0`**（2026-11-02 定）。

原始数据怎么来（质量绩效从哪个系统取、成本怎么算）**不进本期范围**：打分人拿到什么数就对照什么数，系统只认档位，不认原始量纲。

| # | 能力项 | 打分依据（人工对照，不入代码） |
|---|---|---|
| A1 | PN 质量绩效 | 质量绩效分：≥95 → 1；85–95 → 0.7；75–85 → 0.5；60–75 → 0.3；<60 → 0 |
| A2 | 交付达成率 | ≥98% → 1；95–98% → 0.7；90–95% → 0.5；85–90% → 0.3；<85% → 0 |
| A3 | 合格率 | ≥99.5% → 1；98.5–99.5% → 0.7；97–98.5% → 0.5；95–97% → 0.3；<95% → 0 |
| A4 | 成本 | 同 PN 比价：最低 → 1；贵 3% 内 → 0.7；贵 3–8% → 0.5；贵 8–15% → 0.3；贵 15% 以上 → 0 |
| A5 | CFT 飞行稽查 | 通过且无整改项 → 1；通过有小项 → 0.7；有条件通过 → 0.5；整改未闭环 → 0.3；不通过 → 0 |
| A6 | 供应商质量服务分 | 与 A1 同向，按分数段同上 |

| # | 意愿项 | 打分依据（人工对照，不入代码） |
|---|---|---|
| W1 | 降价意愿 | 主动提方案 → 1；愿谈 → 0.7；看条件 → 0.5；推诿 → 0.3；拒绝 → 0 |
| W2 | 建库意愿 | 已建/愿建 → 1；可谈 → 0.7；需分摊成本 → 0.5；拖延 → 0.3；拒绝 → 0 |
| W3 | 紧急交付意愿 | 有富余、3 天内可加量 → 1；可加量需 1 周 → 0.7；小幅调剂 → 0.5；需 1 个月 → 0.3；明确拒绝 → 0 |
| W4 | 沟通态度 | 主动同步 → 1；配合 → 0.7；公事公办 → 0.5；消极 → 0.3；推责 → 0 |
| W5 | 回复及时率 | ≥95% → 1；85–95% → 0.7；70–85% → 0.5；50–70% → 0.3；<50% → 0 |
| W6 | 产能弹性 | 同 W3 口径，看「为我方让出多少」，不看总产能 |

**W6 口径必须写死**：不是「总产能多大」，是「缺口时愿不愿意为我方让出多少」。总产能已在供需模块维护，再录一遍会打架。

**上表是参照，不是校验**：系统不拿原始数据反算档位，打分人打了 0.7 就存 0.7。理由见 §3。

## 3 五档制：1 / 0.7 / 0.5 / 0.3 / 0

```
档位分 × 100 = 折算分
```

| 档位 | 折算分 | 距中点 | 语义 | 与下一档的跨度 |
|---|---|---|---|---|
| 1.0 | 100 | +50 | 优秀 | 30 |
| 0.7 | 70 | +20 | 良好 | 20 |
| 0.5 | 50 | 0 | 中性 | 20 |
| 0.3 | 30 | −20 | 差 | 30 |
| 0 | 0 | −50 | 不可接受 | — |

**非等距，是有意为之，保留**：

1. **与份额模块 QDC 完全同源**（`QDC_SCORES = 1 / 0.7 / 0.5 / 0.3 / 0`）。团队已经熟悉这套刻度，规则页可以共用一套定义，录入表单交互也一致。这条是最大的好处，不要另造一套。
2. **两端 30、中间 20**：从「良好」到「优秀」要跨一大步，抑制「人人打 1 分」的通胀；从「差」到「不可接受」也有明显落差，便于判死刑。
3. **五档够用**：6 项加权后的分值是连续量，5 档 × 6 项的组合同样能拉开点位，不需要 7 档 10 档。

**三条必须写死的规则**：

1. **空 ≠ 0**。没评 = 空（null），评了判负 = 0。表单里默认是空，0 必须手动选。两者在库里、在图上是两回事：空走「未评级」，0 是实打实的差评。
2. **0.5 档 = 中性 = 不过关**。阈值 50 用严格大于判定，所以 12 项全打 0.5 的供应商能力 50、意愿 50，落在「观察退出」。逻辑自洽（全中性 = 没有亮点 = 不值得加注），但要提前打招呼，规则页写一句，免得供应商来问。
3. **比较前先 `round(x, 1)`**。5 档加权容易出现 50.0000001 这种值，直接比大小会误判成「过关」。先取 1 位小数再比。

**单项 0 不翻盘，靠牌解决**：A1 质量绩效打 0、其余 5 项全打 1.0，能力分仍有 75（0×25% + 1×75%），照样进「战略伙伴」。所以一票否决**不做成第 13 项，也不做成加权规则**，而是独立于 12 项的红黄牌（见 §5.1）。分数该多少就是多少，否决另走一条线。

## 4 得分

```
能力分 = Σ(wᵢ × sᵢ) / Σ(wᵢ)      仅对已填项求和
意愿分 = Σ(wᵢ × sᵢ) / Σ(wᵢ)
```

分母是「已填项的权重和」，不是固定 1，所以缺 1–2 项不会把分数拉低（缺失本身另有标记，见 §6）。

## 5 象限

十字线**定在 50 / 50**，可配置。

**阈值 = 十字线画在哪个位置**，也就是「多少分算过关」。它是四象限唯一的判定依据，位置一动，同一家供应商的去向就变。示例：能力 62 / 意愿 45 的一家供应商 —— 线画 60 落在「强势依赖」（保供 + 找替代），线画 70 落在「观察退出」（不新增 + 立项切换）。阈值是及格线，必须写进规则页。

**判定用严格大于**：`能力 > 50` 且 `意愿 > 50` 才算过关，正好 50 分不过关。原因是 0.5 档正好折算 50 分，若用 `≥`，六项全打 0.5 的供应商就会整体落进「战略伙伴」，这是错的。

| 位置 | 名称 | key | 判定 | 动作 |
|---|---|---|---|---|
| 右上 | 战略伙伴 | `partner` | 能力 > 50 且 意愿 > 50 | 加份额、优先新项目、联合降本 |
| 右下 | 强势依赖 | `dependent` | 能力 > 50 且 意愿 ≤ 50 | 保供优先、启动第二来源、高层对话 |
| 左上 | 重点培养 | `nurture` | 能力 ≤ 50 且 意愿 > 50 | 给辅导与试单、份额设上限 |
| 左下 | 观察退出 | `exit` | 能力 ≤ 50 且 意愿 ≤ 50 | 不新增份额、变更单立项切换 |
| 灰色 | 未评级 | `incomplete` | 任一维有效项 < 4 | 补录，不上图 |

配色：绿 `#16a34a` / 蓝 `#2563eb` / 琥珀 `#d97706` / 红 `#dc2626` / 灰 `#94a3b8`。

**两条硬约束**：

1. **不同工艺段不混在一张图**（模组与电芯的供应商能力不可比）。默认按段筛选，跨段时给分面视图。
2. 图上另画一条**本期中位数虚线**，只作水位参考，**不参与判定**。象限必须用绝对阈值，否则「人群整体变差」时点位不动，看不出恶化。

## 5.1 红黄牌

**牌记在供应商级，不是 PN 级。** 一次质量事故是整家公司的事，不会只影响一个 PN。同一供应商的所有物料评价都吃这张牌。

**打牌 = 两维归零**（2026-11-02 定）。

| 牌 | 含义 | 计分 | 图上 | 动作 |
|---|---|---|---|---|
| 红牌 | 一票否决 | **能力、意愿一律 0 分** | 原点（0,0），红圈 + 叉 | 停止新增份额，启动替代 |
| 黄牌 | 警告 | **能力、意愿一律 0 分** | 原点（0,0），黄圈 | 不新增份额，限期整改 |
| 无牌 | — | 按档位算 | 按分数落点 | — |

**牌一打，两维直接归零**，不再看 12 项档位。能力 0 / 意愿 0 天然落「观察退出」—— 象限判定规则一行都不用改，是分数变了，不是判定多了一条分支。

**档位原值不覆盖，只在算分时归零**：

- `tier_a1..w6` 保留打分人填的数，抽屉里照常看到「他当时打了什么」。
- `cap_score / will_score` 快照写 0。
- 解牌后按原档位重算，分数自动回来。若打牌时把档位改成 0，解牌后 12 项就永远是 0 了 —— 这是数据事故，不能这么干。

**红牌与黄牌的区别在标签和动作，不在分数**：两者都沉到原点，凭描边颜色区分（红圈 + 叉 / 黄圈），统计上分开计数（红牌数单独进统计条）。业务读法是「红 = 停止新增并启动替代」「黄 = 限期整改、不新增」。

**两条来源**：

1. **手工打牌**（主）：质量事故、稽查不通过、重大交付事故。打牌必须填原因和打牌人，可追溯。
2. **系统提示**（辅）：A1 质量绩效或 A5 稽查打了 0 → 抽屉里提示「建议红牌」，**不自动生效**。一票否决是重大动作，得有人按下去。

**生效与解除**：

- 牌有起止日期，`effective_from` 起生效，`effective_to` 为空 = 仍在生效。
- 只手工解除，必须填解除原因。不做「到期自动失效」—— 事故闭环是人判断的，不是日历判断的。
- 同一供应商同时最多一张生效牌。打新牌时若已有生效牌，旧牌的 `effective_to` 置为今天（改判），并在备注里留痕。
- 解牌后**只重算牌生效区间内的月份**：历史月份仍记 0 分，才叫可追溯。

## 6 缺失处理

1. **单项缺失** → 该项不进加权，其余按权重重归一，记录 `filled` 数。
2. **任一维有效项 ≤ 3**（12 项里一半以下）→ 该维不出分，整条 `quadrant = incomplete`，不进四象限，只进明细表「待补录」。
3. **禁止默认值填充** —— 不填不猜，缺就是缺，图上空心点。
4. **空与 0 严格区分**：库里 `NULL` = 未评，`0` = 评为不可接受。表单默认空，0 需手动选；两者在统计里分开计数。
5. **同 PN 只有 1 家供应商时，A4（成本）没有比价对象** —— 打分人只能凭绝对值判断，在明细里标「无参照」，不阻断录入。
6. **牌优先于缺失判定**：牌生效期间，不管 12 项填了几项，一律 0 分、`exit`，不进「未评级」。解牌后按实际填写情况重新判定是否 `incomplete`。

## 7 权重

**组内业务权重，两组各自合计 100%**（2026-11-02 定）。

| 维度 | 指标 | 权重 | 为什么给这个数 |
|---|---|---|---|
| 能力 | PN 质量绩效 | **25%** | 质量是第一道门槛，占比最高 |
| 能力 | 交付达成率 | **20%** | 直接影响停线 |
| 能力 | 合格率 | **20%** | 与质量绩效互为交叉验证 |
| 能力 | 成本 | **20%** | 采购核心指标之一 |
| 能力 | CFT 飞行稽查 | **5%** | 事件型数据，多数供应商一年不到一次，权重低 |
| 能力 | 质量服务分 | **10%** | 与质量绩效有重叠，避免重复计分 |
| 意愿 | 降价意愿 | **20%** | |
| 意愿 | 建库意愿 | **15%** | |
| 意愿 | 紧急交付意愿 | **30%** | 唯一能反映「出事时救不救」的项，给最高 |
| 意愿 | 沟通态度 | **10%** | 主观性最强，压低 |
| 意愿 | 回复及时率 | **10%** | 与沟通态度同源，两项合计 20% |
| 意愿 | 产能弹性 | **15%** | |

**校验**：能力组 6 项合计必须 = 100%，意愿组 6 项合计必须 = 100%。配置接口不接受总和不等于 100 的方案。

**存权重快照**：每条评价写入时把当时的权重 JSON 和 `formula_version` 存下来。改权重只影响新评价，不回头改旧结论 —— 否则去年发布的「观察退出」会随权重调整变成「重点培养」，说不清。

**等权作为回退项保留**：配置里留 `preset` 字段（`business` / `equal`），一个开关切回 6 项等距，用于验证「业务权重到底把结论带偏了多少」。对比口径见 §10 迁移视图。

## 8 数据表

```sql
supplier_segments              -- 一行 = 期间 × 物料 × 供应商
  id, period('2026-10'), material_id, supplier_id
  -- 12 个档位字段，取值只能是 0 / 0.3 / 0.5 / 0.7 / 1，NULL = 未评
  tier_a1, tier_a2, tier_a3, tier_a4, tier_a5, tier_a6   REAL
  tier_w1, tier_w2, tier_w3, tier_w4, tier_w5, tier_w6   REAL
  cap_score, will_score  REAL   -- 写入时算好，快照
  quadrant    TEXT     -- partner/dependent/nurture/exit/incomplete
  card_snapshot TEXT   -- 写入时生效的牌：red / yellow / NULL（快照，解牌不改历史行）
  cap_filled, will_filled INT   -- 按实际填写数记，与牌无关
  weight_snapshot TEXT -- JSON
  formula_version TEXT
  evaluator TEXT, evaluated_on DATE, note TEXT
  UNIQUE(period, material_id, supplier_id)

supplier_segment_configs      -- 单行全局配置
  id, threshold_cap, threshold_will, weights JSON,
  preset(business|equal), updated_at

supplier_cards                -- 红黄牌（供应商级，与评价行解耦）
  id, supplier_id
  card          TEXT    -- yellow / red
  reason        TEXT    -- 打牌原因（必填）
  effective_from DATE   -- 生效日
  effective_to   DATE   -- NULL = 仍在生效；解除时写入
  created_by TEXT, created_at
  released_by TEXT, released_at, release_reason
  -- 同一供应商同时最多一张生效牌；打新牌时旧牌 effective_to 置今天
```

库里**只存档位，不存原始值**（质量绩效 92.3 分、单价 4.15 元这类）。原始数据留在各自系统，本模块不复制一份 —— 复制就会失真、就会过期。

**牌不挂在评价行上**：挂行上会导致同一供应商 3 个 PN 要打 3 次牌，也表达不了「牌是月中打的、评价是月末录的」。查询时按 `supplier_id` 关联当前生效牌，`redline` 是写入时的判定快照。

不新增主数据表：物料、供应商、工艺段（`materials.segment`）全部复用。

## 9 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/supplier-segments` | 点集，按 period / material / supplier / segment / project 过滤 |
| GET | `/api/supplier-segments/summary` | 各象限家数、平均分、数据完整率 |
| GET | `/api/supplier-segments/periods` | 可选期间列表 |
| POST | `/api/supplier-segments` | 新增（同期间同物料同供应商则覆盖） |
| PUT / DELETE | `/api/supplier-segments/{id}` | 改 / 删 |
| GET | `/api/supplier-segments/prefill` | 上期档位（复制上期用） |
| GET | `/api/supplier-segments/history` | 单点跨期落点轨迹 |

打牌 / 解牌后**必须回写受影响评价行** —— 否则牌打了、图上不动。受影响 = **评价月份落在牌生效区间 `[effective_from, effective_to]` 内**的行。不是全量重算：解牌只影响解除日之后的月份，历史月份留着「当时在牌上、记 0 分」的记录才叫可追溯。

## 10 页面

沿用「L0 概览 → 抽屉详情」两层。

**顶部固定区**：期间选择 · 项目筛选 · 工艺段筛选 · 视图切换（象限图 / 明细表 / 迁移）
**统计条**：参评条目数 · 战略伙伴数 · 观察退出数 · **红牌数** · 未评级数

**主图（四象限散点）**

- 点 = 一家供应商在一个 PN 上的一次评价
- 气泡大小统一（P0 未接份额接口；P1 再按供货量映射，不要先画个假的）
- 颜色 = 象限；未评级点空心灰边
- **牌点沉在原点**（0,0）：红牌红圈 + 叉，黄牌黄圈。多家同时打牌会完全重叠 → 按数量放大半径、中心显示数字，点击展开这一堆的列表。不加随机偏移，坐标不能造假。
- 标注只给三类：红牌 / 双低 / 独供 —— 全标会糊成一团
- 悬停：供应商 + PN + 两维分 + 12 项档位 + 牌
- 点击 → 右侧抽屉

**右侧抽屉**

- 顶部一条牌带：当前牌 + 打牌原因 + 打牌人 + 生效日，右侧「打牌 / 解牌」按钮
- 雷达图（能力 6 维、意愿 6 维双系列，按档位 × 100 画）

**打牌弹窗**

供应商（默认带出）· 红/黄 · 原因（必填，最少 5 字）· 生效日（默认今天）· 打牌人。已有生效牌时提示「当前为 X 牌，确认后旧牌于今日终止」。

**明细表**：可排序、按象限筛、按牌筛

**迁移视图（P1）**：上期 → 本期箭头，谁掉档、谁升档。老板真正关心的是这个。

## 11 Excel 导入

模板 `frontend/public/templates/segment-import-template.xlsx`（生成脚本 `scripts/make_segment_template.py`），19 列：

```
期间 | 物料PN | 物料名称 | 供应商代码 | 供应商名称 |
质量绩效 | 交付达成率 | 合格率 | 成本 | CFT稽查 | 质量服务分 |
降价意愿 | 建库意愿 | 紧急交付 | 沟通态度 | 回复及时率 | 产能弹性 |
打分人 | 备注
```

档位列带下拉（1 / 0.7 / 0.5 / 0.3 / 0），另附「填写说明」sheet。

**校验（一行错 → 整批不写，返回逐行 errors）**：

1. 期间 `YYYY-MM`；该列为空时用导入弹窗里选中的月份（`default_period`）
2. PN 必须存在于 `materials.pn`；供应商代码必须存在于 `suppliers.code`（不按名称匹配）
3. 12 个档位只接受 `1 / 0.7 / 0.5 / 0.3 / 0`；也接受 `100 / 70 / 50 / 30 / 0` 与 `70%`（÷100 归一）。**不就近取整**，`0.8` 直接报错
4. 空单元格 = 未评，允许；**12 项全空的行拒绝**
5. 同一文件内 期间 + PN + 供应商 重复 → 报错，不静默合并
6. 已存在的同一条评价 **覆盖更新**（`updated` 计数），不新增重复行

**为什么整批不写**：批量补录最怕「错了 1 行、进了 49 行」，事后没人对得出来少的是哪一行。

## 12 边界：不做什么

| 不做 | 原因 |
|---|---|
| 不写 `suppliers.risk_level` | 地图着色是另一套规则，未定；先不污染主数据 |
| 红黄牌 ≠ 地图红黄绿 | 牌是处罚/警示，只有红黄没有绿；`risk_level` 是风险等级。两者不互相回写 |
| 不参与份额 QDC | Q/D/C 是份额配比用的评分，单位与口径都不同，混用会出错 |
| P0 不进预警中心 | 先让数据跑起来，规则稳定后再接 |
| 不自动铺全库 | 只评重点物料；未评价的物料单列「应评未评」，不生成占位记录 |
