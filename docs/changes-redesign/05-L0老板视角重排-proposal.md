## 2. 诊断：第一屏装错了东西

老板来这个页面只关心三件事（按紧急度）：

| 优先级 | 老板的问题 | 现在第几屏能回答 |
| --- | --- | --- |
| ① | **有没有雷？哪个项目/哪张单要炸、拖了多久** | 第 2 屏（E，803px 起） |

## 4. 新增块设计：老板头条

> ⚠ **本节的"头条"形态已被 §11 改写**：「拖最久 11 天 —— 郑工 / 供应商整改计划确认」是人名 + 任务名，
> **属细节**。修正后的头条**只到项目级**，且要和「项目健康度」合并成一块（§11.4）。
> 本节保留作为"结论带"的设计参考（生成规则、边界分支仍然有效）。

放在标题栏正下方，**全宽、单块、约 90~110px**。一次讲完"问题在哪、有多严重、找谁"。

```
┌────────────────────────────────────────────────────────────┐
│ 🔴 3 个项目全部落后于时间进度                     [看全部 10 项 →] │
│    最严重「动力电池 PACK 产线」：时间已过 82%，任务只完成 44%          │
│    超期 6 项（4 张单），拖最久 11 天 —— 郑工 / 供应商整改计划确认        │
└────────────────────────────────────────────────────────────┘
```

**生成规则（必须由数据算，不许写死话术）**

| 行 | 内容 | 数据来源 |
| --- | --- | --- |
| 主句 | `{滞后项目数}/{总项目数} 个项目落后于时间进度` | `avg_deviation > 0` 计数 |
| 次句 | 最严重项目：`时间已过 {avg_time_rate}%，任务只完成 {task_done_rate}%` | 取 `avg_deviation` 最大者 |
| 三句 | `超期 {n} 项（{m} 张单），拖最久 {d} 天 —— {责任人} / {最久那项}` | `summary` + `alerts[0]` |
| 按钮 | 「看全部 N 项 →」跳 §第一档的待办项完整列表 | |

**边界分支**（必须全部覆盖，否则上线命中即白屏 —— 见技能 §5.6）
1. 无滞后项目 → 绿：`所有 N 个项目都不落后于时间进度`
2. 无变更单 → 默认灰：`还没有变更单，点右上角「新建变更单」开始记录`
3. 无超期但有临期 → 黄：主句不变，三句改 `无超期；{k} 项将在 3 天内到期`
4. 所有任务已完成 → 绿：`全部 {n} 项任务已完成`

> 现状已有 4 处独立的「一句话结论」（燃尽图 / 类型饼图 / 项目饼图 / 偏差榜）。
> 头条不是第 5 处 —— 它是**把其中最关键的三句拎出来，放到最贵的位置**。
> 四张图各自的结论句**保留**（它们服务于读图的人），头条服务于**不读图的人**。

## 5. 新增块设计：进度对比（时间 vs 完成率）

一行两张条，**成本约 70px**，替代燃尽图 378px 里 80% 的信息量：

```
时间进度  ████████████████████░░░░░░  54.5%   已经过了这么多日子
任务完成  ██████████████░░░░░░░░░░░░  36.4%   实际只做了这么多
                                       落后 18.1 个点
```

- 口径 = 全局（所有进行中的单）：`计划应完成 / 全部叶子` vs `已勾选 / 全部叶子`
- 这两条与燃尽图**同源**（都来自 `/changes/burndown` 的 `plan_remaining` / `actual_remaining`），不是新口径
- 好处：**老板不用看懂"两条线"**，只看两个条谁长谁短 —— 而且这恰好是 3 个项目卡片上已有的同一个指标（`avg_time_rate` vs `task_done_rate`），**口径统一、可向上汇总**

> ⚠ 这一条请你重点评估：它会让"燃尽图"从第一屏消失。
> 如果你觉得燃尽图那条"60 天水平线"的视觉冲击不可替代，我们可以**两个都留**（燃尽图降到第 2 屏 240px）。

## 6. 三个备选版面（请你选一个）

### 方案 A · 问题清单优先（我的推荐）

```
第 1 屏  【老板头条】+【统计卡 ×5】+【最需要盯的待办项 · 5 条】

第 2 屏  【进度对比】+【整体燃尽图 240px】
第 3 屏  【项目卡片墙（压缩）】

```
- 优点：最贴你的原始诉求；手机上滚 1 屏就到结论
- 代价：燃尽图从第一屏消失

### 方案 B · 趋势优先

```
第 1 屏  【老板头条】+【统计卡 ×5】+【进度对比】+【整体燃尽图 240px】

```
- 优点：第一屏保留"趋势"视角；改动最小（只挪待办项 + 新增头条 + 缩燃尽图）
- 代价：老板第一眼看得到"落后多少"，但看不到"具体是哪张单"

### 方案 C · 分屏 Tab（不滚动，点着看）

```
第 1 屏  【老板头条】+【统计卡 ×5】
         [ 盯盘 ● | 分析 | 项目 ]   ← 三个 Tab
  盯盘   = 最需要盯的待办项 + 进度对比 + 燃尽图
  分析   = 构成条 + 两张饼图 + 偏差榜 + 超期分档
  项目   = 卡片墙（进行中/已归档 + 搜索）
```

- 优点：每一屏都短，手机上不用长滚；分析内容有自己的家，主页极干净
- 代价：多一层点击；"项目卡片墙"是导航入口，藏进 Tab 可能影响日常使用习惯

### Q1 为什么决定一切

| 场景 | 版面取向 |
| --- | --- |
| **例会投屏** | 第一屏要能"指着一块说话" → 信息可密，块要少而大，**不要 Tab**（投屏上没人点） |
| **手机日常刷** | 一屏一个结论，字要大，**可以 Tab**，长表格要折叠 |
| **两者都要** | 默认按投屏排（桌面），手机自适应降级 —— 这也是现状的做法 |

### Q2 为什么必须先问

现在 4 张图各自有一句结论，但**它们都在"平均"这个维度上做文章**（类型占比、项目占比、偏差均值）。
如果你心里的"问题"是 **"哪个物料/供应商反复出问题"**，那现有数据维度里**没有这个视角**（要新增聚合），得提前说，否则第一屏做完了还是答不了你的问题。

### 14.2 实现口径（★ 需要你知道我做了哪个选择）

「一直放在最上面」有两种解释，我按**更强的那一种**实现，因为弱的那一种（只保证顺序第一）

| --- | --- | --- |

| 脚本 | 改法 | 理由 |
| --- | --- | --- |
| `scripts/_tmp/verify_home.mjs` | A/B/D/E 节的 URL 加 `todos=1&trend=1`；五色图例的切片边界从「整体燃尽图」改成「最需要盯的待办项」 | 燃尽图移到折叠区后，原边界会把饼图的 43% 一起切进 5 项图例里（实测 143% 假失败） |

| `scripts/verify_mobile.mjs` | 第 1 节改 `?todos=1`；**截断损失断言豁免 `el.closest("button")` 内的 `.truncate`** | 折叠头摘要的 `truncate` 是**有意的单行预览**（点开即见全文），不属"关键信息被吃掉"（原报 440px 假失败） |
