## 0. 一句话定位

变更管理 = 记录**「稳态数据被改变的过程」**，把一次变更拆成**可执行、可跟踪、可追责的任务树**。

它真正管的不是"进度百分比"，而是**承诺兑现情况**：

> 会上定下「这件事 10-01 开始、10-16 结束、王强负责」→ 这就是一个承诺。
> 时间不用任何人管，它自己往前走。到点了事没勾完成，系统就该把它拎出来：**哪件事、超期几天、谁负责**。

三个回答：
1. 现在有哪些变更在跑？（项目卡片墙 + Summary）
2. 每件事进行到哪了、谁负责？（甘特图 + 任务树）
3. 哪件事要黄了？（超期 / 临期预警 + 责任人）

## 1. 边界与原则

### 1.1 锚点

变更单的主锚点 = **项目 × 物料（PN）**，与库存推算单元、份额记录的锚定方式同构。

| 维度 | 必要性 | 说明 |
| --- | --- | --- |
| 项目 | **必填** | 变更一定是"某个项目上的变更" |
| 物料 PN | **必填** | 一期**只做物料级变更**，不存在项目级变更 |
| 供应商 | **可选** | 「替换供应商」这类变更本身就在改变供应商关系，强制绑定自相矛盾 |
| 变更类型 | **必填** | 全局字典，两种以上 |

**一张变更单 = 一个物料。** 同一物料在同一项目下**可以同时存在多张**未完成变更单（如先"设计变更"、再"供应商切换"）。

### 1.2 三条硬原则

1. **不自动改写其他模块的数据。** 变更管理只做"过程记录 + 决策辅助"；变更结果是否落回主数据，由人确认（二期半自动回写，且必须人工点确认）。与地图/图表同源：数据保真。
2. **不造假数据。** 所有派生指标（超期天数、燃尽线）只从真录入的字段推导，不补点、不推算未来。
3. **归档只作用在变更模块内部。** 项目是供需/份额/库存共用的主数据，归档**不能**影响其他模块的项目选择器。

## 3. 数据模型

### 3.1 表清单（4 张新表，不动任何既有表）

| 表 | 作用 | 备注 |
| --- | --- | --- |
| `change_types` | 变更类型字典（全局） | 极简，只有名字 |
| `changes` | 变更单 | 项目 × 物料 × 类型 |
| `change_tasks` | 待办项 / 子项（单表自引用） | 核心表 |
| `change_archives` | 归档记录（项目级 + 单张级） | 只影响变更模块 |

**不建的表**（v0.1 提过，已砍）：
- ~~`change_type_tasks` 模板任务~~ → 用户明确"类型只是一个名字"（#26）
- ~~`change_logs` 变更日志~~ → 用户只否掉了"改期留痕"，#13；整体日志未要，放二期
- ~~`change_burndown_snapshots`~~ → 燃尽是纯派生，不存快照

### 3.2 `change_types` — 变更类型字典

```sql
CREATE TABLE change_types (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        VARCHAR(100) NOT NULL,                 -- 类型名（如 供应商切换 / 设计变更 / 成本优化）
    sort_order  INTEGER      NOT NULL DEFAULT 0,
    is_active   BOOLEAN      NOT NULL DEFAULT 1,       -- 停用而非删除
    remark      TEXT,
    created_at  DATETIME     NOT NULL DEFAULT (CURRENT_TIMESTAMP),
    updated_at  DATETIME     NOT NULL DEFAULT (CURRENT_TIMESTAMP)
);
```

**删除策略**：被任何变更单引用过的类型**只能停用，不能删除**（避免历史单出现孤儿引用）。零引用才允许真删。

**作用域**：全局一个库，一次维护、所有项目共用（#26）。

### 3.3 `changes` — 变更单

```sql
CREATE TABLE changes (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,   -- 序号（即用户要的"序号"，不做 CHG-xxxx 单号）
    project_id      INTEGER NOT NULL,                    -- FK projects.id
    material_id     INTEGER NOT NULL,                    -- FK materials.id
    change_type_id  INTEGER NOT NULL,                    -- FK change_types.id
    supplier_id     INTEGER,                             -- FK suppliers.id，可选
    title           VARCHAR(200) NOT NULL,               -- 变更标题
    description     TEXT,                                -- 变更内容
    owner           VARCHAR(100),                        -- 责任人（自由文本）
    status          VARCHAR(20)  NOT NULL DEFAULT 'active',  -- active / done / voided
    plan_start      DATE,                                -- 计划开始（由任务汇总，冗余）
    plan_end        DATE,                                -- 计划结束（由任务汇总，冗余）
    completed_at    DATETIME,                            -- 实际完成时刻（自动写入）
    archived_at     DATETIME,                            -- 归档时刻（NULL = 未归档）
    is_removed      BOOLEAN      NOT NULL DEFAULT 0,     -- 软删除
    remark          TEXT,
    created_at      DATETIME     NOT NULL DEFAULT (CURRENT_TIMESTAMP),
    updated_at      DATETIME     NOT NULL DEFAULT (CURRENT_TIMESTAMP)
);
CREATE INDEX ix_changes_project  ON changes(project_id);
CREATE INDEX ix_changes_material ON changes(material_id);
CREATE INDEX ix_changes_type     ON changes(change_type_id);
CREATE INDEX ix_changes_status   ON changes(status);
CREATE INDEX ix_changes_plan_end ON changes(plan_end);
```

**说明**：
- `plan_start / plan_end` 是**冗余汇总字段**（服务端从叶子任务算出后回写），用于列表排序与卡片预警，避免每次查询都递归树。
- **不存 `progress` 字段** —— 进度是纯派生（§5），落库会不一致。
- `archived_at` 冗余存一份，便于列表快速过滤；权威记录在 `change_archives`。

### 3.4 `change_tasks` — 待办项 / 子项（核心）

```sql
CREATE TABLE change_tasks (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    change_id    INTEGER NOT NULL,                  -- FK changes.id
    parent_id    INTEGER,                           -- 自引用，NULL = 一级待办项
    level        INTEGER NOT NULL DEFAULT 1,        -- 1..5（封顶 5 层）
    seq          INTEGER NOT NULL DEFAULT 0,        -- 同级排序（甘特图自上而下）
    name         VARCHAR(200) NOT NULL,             -- 任务名
    description  TEXT,
    owner        VARCHAR(100),                      -- 责任人（不填则继承 changes.owner）
    plan_start   DATE,                              -- 计划开始
    plan_end     DATE,                              -- 计划完成（预警依据）
    is_done      BOOLEAN NOT NULL DEFAULT 0,        -- 勾选完成
    done_at      DATETIME,                          -- 完成时刻（勾选瞬间自动写；燃尽图唯一数据源）
    is_removed   BOOLEAN NOT NULL DEFAULT 0,        -- 软删除
    remark       TEXT,
    created_at   DATETIME NOT NULL DEFAULT (CURRENT_TIMESTAMP),
    updated_at   DATETIME NOT NULL DEFAULT (CURRENT_TIMESTAMP)
);
CREATE INDEX ix_change_tasks_change ON change_tasks(change_id);
CREATE INDEX ix_change_tasks_parent ON change_tasks(parent_id);
CREATE INDEX ix_change_tasks_end    ON change_tasks(plan_end);
```

**说明**：
- **去掉 `status` 字段**：任务的"状态"完全由 `plan_end` + `is_done` + 今天**推导**出来（§5.1），不落库、不会不一致、不用人维护。
- **去掉 `weight` 字段**：不做人天加权（#11 按时间自动算）。
- `level` 只做校验（封顶 5 层）与缩进渲染，不做业务判断。
- 折叠状态**不落库**，存前端 localStorage（#22）。

### 3.5 `change_archives` — 归档记录

```sql
CREATE TABLE change_archives (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    scope        VARCHAR(10) NOT NULL,             -- 'project'（整项目归档） / 'change'（单张归档）
    project_id   INTEGER NOT NULL,                 -- 两种粒度都记项目，便于按项目检索
    change_id    INTEGER,                          -- scope='change' 时必填；scope='project' 时为 NULL
    archived_at  DATETIME NOT NULL DEFAULT (CURRENT_TIMESTAMP),
    remark       TEXT,                             -- 归档说明（可选）
    created_at   DATETIME NOT NULL DEFAULT (CURRENT_TIMESTAMP)
);
CREATE INDEX ix_change_archives_project ON change_archives(project_id);
CREATE INDEX ix_change_archives_change  ON change_archives(change_id);
```

**归档语义**（严格遵守 #3 与 §1.2 硬原则 3）：
- **整项目归档** = 给该项目下**当前所有**变更单写 `archived_at`，并记一条 `scope='project'` 的记录。
- **单张归档** = 只给那一张写 `archived_at`，记一条 `scope='change'`。
- **只读**：已归档的变更单禁止增删任务、改时间、改状态。
- **取消归档** = 清掉 `archived_at` 并删除对应 `change_archives` 记录，退回活跃。
- **对其他模块零影响**：projects / materials / suppliers / supply_relations 等表**一个字段都不动**。

### 3.6 迁移方式

新表走 `Base.metadata.create_all`（`main.py` 的 lifespan 已自动执行），**`migrations.py` 无需改动**（它只处理"改已有表结构"的场景）。

> **结论：本次对现有数据零风险。**

## 4. 状态与生命周期

### 4.1 变更单三态

| 状态 | 值 | 何时进入 | 表现 |
| --- | --- | --- | --- |
| 进行中 | `active` | 新建时默认 | 列表默认显示 |
| 已完成 | `done` | ① 所有叶子任务勾完 → **自动**；② 手动标记（若有未勾任务，弹确认提示"还有 N 项未勾，确定标记完成吗"）| 记录 `completed_at` |
| 已作废 | `voided` | 手动点"作废"（变更中途出问题、停止执行）| 默认从活跃列表隐藏，可从"已作废"筛出 |

```
新建 ──► 进行中 ──┬──► 已完成（任务全勾 / 手动）──► 归档
                  └──► 已作废 ──┬──► 一直保留（可查、可恢复）
                                └──► 删除（软删 is_removed=1，默认不显示）
```

**要点**：
- 变更单**可随时删减任务、改任务的开始/完成时间**（用户明确要求）。
- 作废 ≠ 删除。作废是"这件事不做了但记录留着"，删除是"这条不要了"。
- 删除用**软删**（对齐 `products.is_deleted` 约定），数据可恢复。

**★ 施工补丁（2026-10-05 实测后补）——自动完成必须是「双向同步」**：

初版只在"勾选那一刻"评估一次（叶子全勾 → done），实测踩到两个缺口：

1. **假完成**：单子当时只有 1 个任务，勾上 → 立刻 done；随后又加了新任务，状态却停在 `done`（加完任务反而变成"已完成"的单子显然是错的）。
2. **假未完成**：把最后一条没做完的任务删掉 → 叶子全完成，状态却不会自己变成 `done`。

已改为：**任何任务事实变化（新增 / 删除 / 勾选 / 取消勾选）之后，都由 `_sync_status_from_tasks()` 单向同步一遍**：

| 叶子任务事实 | 单子状态 |
| --- | --- |
| 有叶子，且全部已勾 | `done`（`completed_at` = 最后一次勾选时刻）|
| 有叶子，且存在未勾 | `active` |
| 一个叶子都没有 | 不改（保留手动设置，避免空单被反复翻状态）|

**作废单 / 归档单不参与同步**（它们的状态不再随任务变化；归档单本就只读）。

### 4.2 状态与进度的关系

- 状态 = `done` 时，卡片与列表按 100% 展示。
- 状态 = `voided` 时，**不参与任何统计与预警**（不占分母）。
- 状态 = `active` 时，参与预警与燃尽。

## 5. 计算口径（★ 本模块的灵魂）

> 全部为**派生计算**，服务端实时算，不落库。

### 5.1 任务五色状态（怎么"抓"）

输入：`plan_end` + `is_done` + `done_at` + 今天。

| 状态 | 判定 | 配色 | 甘特图上的样子 |
| --- | --- | --- | --- |
| 未到期 | `is_done=0` 且 `plan_end − today > 3` | 蓝 | 实心条按时段 |
| 临期 | `is_done=0` 且 `0 ≤ plan_end − today ≤ 3` | 黄 | 实心条 |
| **超期未完成** | `is_done=0` 且 `plan_end < today` | 红 | 红实心条 + **红色虚线从条尾延伸至今日线**（欠着的部分一眼可见） |
| 按时完成 | `is_done=1` 且 `done_at ≤ plan_end` | 绿 | 绿色条 |
| **迟交完成** | `is_done=1` 且 `done_at > plan_end` | 橙 | 橙条 + 细虚线拉到实际完成日 + **右端小竖标 = 实际完成日** |

配套数值：
- **超期天数** = `today − plan_end`（进行中任务"还欠几天"）
- **迟交天数** = `done_at − plan_end`（已完成任务"当时迟了几天"）

### 5.2 完成率 —— "人给的答案"

```
完成率 = 已完成叶子任务数 ÷ 叶子任务总数
```

- **只数叶子**（#24）：父项不重复计入，避免层数越多数字越虚。
- 父项展示时会显示 `2/3 完成` 这样的分数，帮助人在树上定位。

### 5.3 时间进度 —— "自动的标尺"

```
时间进度 = clamp( (today − 最早 plan_start) ÷ (最晚 plan_end − 最早 plan_start), 0, 1 )
```

分母为 0（所有任务同一天）时，直接用 `today ≥ plan_end ? 1 : 0`。

### 5.4 偏差（真正要看的数）

```
偏差 = 时间进度 − 完成率
```

- 偏差 > 0 → **时间跑在前面，人没跟上**（滞后，越大越危险）
- 偏差 ≤ 0 → 正常或超前

> 举例：变更单剩下 3 个任务，最早 10-01 开始、最晚 10-30 结束，今天 10-20。
> 时间进度 = 19/29 = 66%；完成率 = 1/3 = 33%；**偏差 = +33 个点** —— 一眼看出"这单要黄"。

**两种完成率都要在项目卡上显示**（#34 相关 / Q16）：
- 按任务算（上式）
- 按变更单算 = 已完成变更单数 ÷ 未作废变更单总数

### 5.5 燃尽图

| 线 | 数据源 | 画法 |
| --- | --- | --- |
| 计划线 | 各叶子的 `plan_end` | **阶梯下降**：每到一批计划完成日，剩余数往下掉一阶 |
| 实际线 | 各叶子的 `done_at` | 按实际完成日逐日累计下降 |
| 总数基准 | 叶子总数 | 起点 |

- X 轴范围 = `min(plan_start) → max(plan_end)`，超出今日时自动延伸
- **只依赖已录入的数据，不推算、不补点**

### 5.6 汇总冒泡规则

```
叶子超期/临期 → 父项行显示状态角标（如「1 项超期」）
              → 变更单列表行首色点变红/黄
              → 项目卡片超期数 +1
              → 顶部预警条计数 +1
```

- **父条颜色保持中性灰**（#25），只在**角标、色点、卡片**上出报警色。
- 角标文案：`1 项超期` / `2 项临期` / `2 项未完成`（未完成但不是问题时用中性灰角标）。

## 6. 页面结构

### 6.1 路由与导航

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/changes` | 变更管理（**项目卡片墙** = 老板视角） | 未选项目时的默认视图 |
| `/changes?project=<id>` | 同一页面的**项目视图**（选中项目后切换） | 沿用库存页 L0/L1 的选择器交互 |
| `/changes?risk=overdue` | 同上，落地即筛选"超期" | 供 Dashboard 卡 5 跳转 |

- `App.tsx` 新增一条路由；`SiteSidebar.tsx` 第 20 行「变更管理」从 toast 占位改为 `to="/changes"`。

### 6.2 L0 —— 项目卡片墙（老板视角 · 核心界面）

**一个项目一张卡**，设计目标是"扫一眼就知道哪个项目出事了"：

| 卡上元素 | 内容 |
| --- | --- |
| 项目名 | `code · name` |
| 变更数 | 进行中 N（总 M） |
| 超期 | **红字**：超期变更单 X 张 · 超期待办项 Y 项（鼠标悬停看明细） |
| 临期 | 黄字：临期变更单 Z 张 |
| 完成率 | 两种都要：按任务 58% / 按变更单 46% |
| 最紧急 | 一行小字：`#12 供应商切换 · 王强 · 超期 6 天` |
| 变更类型拆分 | 小幅标签：供应商切换 5 · 设计变更 3 |
| 操作 | 「归档此项目」按钮 |

**排序与筛选**：
- **默认按超期数降序** → 有问题的项目自动浮到最前
- 卡片边框：有超期 → 红边；只有临期 → 黄边；正常 → 灰边
- 顶部：**搜索框**（项目名 / 项目代码）+ **分页**（十几个项目，一页 12 张）+ 状态筛选（进行中 / 已归档）
- 点击卡片 → 进入该项目的 L1 视图

**页头补充**：全局统计条（变更总数 / 进行中 / 超期 / 临期）+ 全局按类型的横条分布图。

### 6.3 L1 —— 项目视图（选中项目后）

从上到下：

1. **顶部预警条**：`🔴 超期 3 ｜ 🟡 临期 5`，点击即筛选下方列表
2. **统计卡**：变更数 / 进行中 / 已完成 / 超期 / 类型种数（去重）
3. **合并甘特图**：该项目所有变更单合成一张，按变更单分块（见 §6.5）
4. **燃尽图**：计划阶梯线 + 实际线（§5.5）
5. **变更单列表**（表格）

| 列 | 说明 |
| --- | --- |
| ● | **行首色点**：红=有超期 / 黄=有临期 / 绿=全完成 / 灰=未开始 |
| 序号 | `id`（用户不要单号） |
| 物料 | PN + 名称 |
| 类型 | 类型名标签 |
| 责任人 | 变更单总责任人 |
| 计划完成 | `plan_end` |
| 完成 | `2/3 · 67%` + 偏差（如 `滞后 33pt`，红字） |
| 状态 | 进行中 / 已完成 / 已作废 |

点击行 → 右侧**详情抽屉**。

**次要位置**：右上角一个「按责任人」切换（**不占大头**，用户明确要求）——把当前项目的预警按人聚合："王强 3 项超期 / 李娜 1 项"。

### 6.4 详情抽屉（Sheet）

沿用项目现有的 `InventoryDetailSheet` / `MaterialDrawerFilter` 交互习惯。三个 Tab：

1. **基本信息**（可编辑）：类型 / 责任人 / 标题 / 描述 / 供应商（可选）/ 状态操作（完成 / 作废 / 删除 / 归档）
2. **甘特图**：这张单自己的甘特图（§6.5）
3. **任务清单**：树形编辑区（增删改、勾选、改责任人/日期、批量粘贴）

### 6.5 甘特图（自绘，零新依赖）

**为什么自绘**：AGENT.md 明确"内网优先离线"，加第三方库是成本最高的一件事。用 div 绝对定位自绘，天然支持"任务树 + 任意层折叠 + 子项缩进"，风格与现有 Tailwind 完全一致。

**两张图**：
| 图 | 位置 | 内容 |
| --- | --- | --- |
| 单张甘特图 | 详情抽屉 → 甘特图 Tab | 这一张变更单的任务树 |
| **合并甘特图** | L1 项目视图 | 该项目**所有变更单**合成一张，按变更单分块（每块可整块折叠） |

**要素**：
- **左列**：任务名（含层级缩进）+ 责任人 + 状态文字/角标
- **右列**：时间轴（日粒度，跨度大时自动切周/月），浅色网格线
- **条**：叶子条按 §5.1 五色；**父条 / 变更单汇总条 = 中性灰**（长度覆盖其下所有子项的时间跨度）
- **今日线**：红色虚线竖线，贯穿全图 → 左边还红着的 = 现在欠着的
- **超期可视化**：红色条 + 红色虚线延伸到今日线（欠的部分）
- **迟交可视化**：橙色条 + 细虚线拉到实际完成日 + 右端小竖标
- **范围**：`min(plan_start) − 3天` ~ `max(plan_end) + 3天` 自动外扩
- **hover**：tooltip 显示 任务名 / 责任人 / 计划起止 / 超期或迟交天数
- **点击条** → 打开该任务的编辑
- **拖拽改期** → **二期**（成本高、易误操作）

### 6.6 折叠规则

- **任意层级可折叠**（#20）：变更单块 ▾、待办项 ▾、子项（叶子无三角）
- **收起后父行仍保留**：汇总灰条 + 状态角标（如「1 项超期」）→ **收起来不丢信息**
- **默认智能展开**（#21）：进入时只自动展开"含超期/临期"的分支，其余收起
- **状态记忆**（#22）：手动折叠的结果存 localStorage，刷新 / 次日进来仍是那个样子
  - key 设计：`changes:collapse:<scope>:<id>`，例如 `changes:collapse:project:12`

### 6.7 配色规范

| 用途 | 颜色 | 应用位置 |
| --- | --- | --- |
| 进行中 | 蓝 | 叶子甘特条 |
| 临期（≤3天） | 黄 | 叶子甘特条 / 角标 / 卡片边框 |
| **超期未完成** | **红** | 叶子甘特条 + 虚线段 / 色点 / 卡片数字 / 副标 |
| 按时完成 | 绿 | 叶子甘特条 / 色点 |
| **迟交完成** | **橙** | 叶子甘特条 + 实际完成日竖标 |
| 父条 / 汇总条 | **中性灰** | 甘特图中的父项与变更单条 |
| 未开始 | 浅灰 | 叶子甘特条 |

> **分工原则**（#18）：**甘特图负责结构（条的中性化），卡片与汇总负责报警（红黄）**。

## 7. 预警机制

### 7.1 规则

| 级别 | 判定 | 配色 |
| --- | --- | --- |
| 已超期 | `plan_end < today` 且 `is_done = 0` | 红 |
| 临期 | `0 ≤ plan_end − today ≤ 3` 且 `is_done = 0` | 黄 |
| 迟交完成 | `is_done = 1` 且 `done_at > plan_end` | 橙（复盘用，不算"待处理"） |
| 未指派 | 任务无责任人（含继承后仍为空） | 灰，单独提示"未指派" |

- 阈值 3 天**不做页面配置**（用户已定 3 天，保持简单）
- 一级与二级任务都参与预警，按 §5.6 冒泡

### 7.2 三个呈现位置

1. **变更页顶部预警条**：`🔴 超期 3 ｜ 🟡 临期 5`，点击筛选
2. **预警明细表**（L0 全局 / L1 项目内各一份）：
   `任务名 | 变更单 | 项目 | 物料PN | 责任人 | 计划完成 | 剩余/超期天数 | 级别`，**按严重度排序**，**必带责任人**，"未指派"标灰
3. **Dashboard 卡 5**（§12.1）

## 8. 录入与编辑

### 8.1 页面内编辑能力矩阵

| 内容 | 编辑方式 | 理由 |
| --- | --- | --- |
| **勾选完成** | 列表 / 树上直接点勾选 | 最高频，一键即改 |
| 任务名 / 责任人 / 起止时间 | 行内编辑（点开即改） | 会上定完时间会现场改 |
| 任务增删 | 树上「+ 添加子项」/ 删除 | 支持多层，逐层加 |
| 父项勾选 | 子项全勾自动；点父项 = 批量全勾/全取消 | #9 |
| 变更单完整字段 | 右侧 Sheet 详情 | 字段多，需要空间 |
| 变更单状态操作 | 列表行内 / 详情内（完成、作废、删除、归档） | 高频操作 |
| 变更类型维护 | 弹窗 / 抽屉（入口：变更页工具栏 + 新建单时下拉旁「+」） | 低频功能不占导航 |

| Excel 批量 | 导入弹窗 | 首次建档 / 批量迁移 |

**即时反馈**：任何修改 toast 提示；失败给中文原因（新字段需登记到 `main.py` 的 `_FIELD_LABELS`）。

### 8.2 Excel 导入（双 sheet）

| sheet | 列 |
| --- | --- |
| `变更单` | 序号 / 项目代码 / 物料PN / 变更类型 / 责任人 / 标题 / 描述 / 状态 |
| `待办项` | 序号 / 变更单序号 / **父项行号** / 层级 / 任务名 / 责任人 / 计划开始 / 计划完成 / 是否完成 |

- **层级表达**：`父项行号`列 —— 留空 = 一级待办项；填 `3` = 第 3 行的子项（层层向上可用）
- **匹配键**：`变更单` 按**序号**匹配（用户明确 #27/Q12）；序号留空 = 新建
- **导入策略**：先校验（项目/物料/类型是否存在、日期合法、层级不超 5 层），**列出错误行再决定是否导入**；结果摘要「新增 x / 更新 y / 跳过 z（含原因）」
- **模板下载**：变更页工具栏 / 导入弹窗提供**空模板下载** → `GET /api/changes/template`（服务端 openpyxl 生成，两个 sheet：`变更单` + `待办项`；表头与导入解析一字不差，另附一行浅灰示例 + 填写说明；示例行的项目代码故意写成不存在的 `PRJ-示例`，即使误导入也只会 skip 报错，不会写脏数据）

### 8.3 责任人输入（自由文本 + 软提示）

用户选择 A（纯自由文本）。为了不让人名打岔，加**零成本软提示**：

- 输入框仍是自由输入，**不校验、不强制**
- 输入框下方一排「最近用过的名字」小标签，点一下即填入（候选来自全库 `changes.owner` + `change_tasks.owner` 去重）
- 任务责任人留空 → 自动继承变更单总责任人（#30）

## 10. 接口清单

> 统一前缀 `/api`。**路由注册顺序有坑**：`/{change_id}` 是 int 参数路由，字面量路由必须注册在它之前，否则 `/api/changes/summary` 会被当成 id 解析报 422。
> `change_types` 独立走 `/api/change-types`，彻底避开这个坑。

### 10.1 变更类型（`/api/change-types`）

| 方法 | 路径 | 说明 | 响应形状 |
| --- | --- | --- | --- |
| GET | `/api/change-types` | 类型列表 | **裸数组** |
| POST | `/api/change-types` | 新增类型 | 对象 |
| PATCH | `/api/change-types/{id}` | 改名 / 停用 / 排序 | 对象 |
| DELETE | `/api/change-types/{id}` | 删除（仅零引用可删，否则 400） | |

### 10.2 变更单（`/api/changes`）

| 方法 | 路径 | 说明 | 响应形状 |
| --- | --- | --- | --- |
| GET | `/api/changes` | 列表。参数：`project_id` / `change_type_id` / `status` / `risk`(overdue,near) / `archived`(0,1) / `q` / `sort` / `page` / `page_size` | **分页对象** `{items,total,page,page_size,total_pages}`（`page_size` ≤ 100） |
| POST | `/api/changes` | 新建变更单 | 对象 |
| **GET** | **`/api/changes/summary`** | 全局统计 + 类型分布（★须在 `/{id}` 之前注册） | 对象 |
| **GET** | **`/api/changes/project-overview`** | **项目卡片墙数据**（按项目聚合，含超期/临期/两种完成率）★须前置 | **裸数组** |
| **GET** | **`/api/changes/alerts`** | 预警明细清单。参数：`project_id` / `level` | **裸数组** |
| **GET** | **`/api/changes/burndown`** | 燃尽数据。参数：`project_id` 或 `change_id` | 对象 |
| **GET** | **`/api/changes/owners`** | 责任人候选（去重，供软提示） | **裸数组** |
| **POST** | **`/api/changes/import`** | Excel 双 sheet 导入。★`file_path` 必须是**绝对路径**（后端 CWD 是 `backend/`） | 结果摘要 |
| **GET** | **`/api/changes/template`** | **空模板下载**（双 sheet + 示例行 + 填写说明）★须前置 | 文件流 |
| **GET** | **`/api/changes/export`** | 导出 Excel（支持单张 / 整项目归档包） | 文件流 |
| GET | `/api/changes/{change_id}` | 详情（含任务树） | 对象 |
| PATCH | `/api/changes/{change_id}` | 改字段 | 对象 |
| DELETE | `/api/changes/{change_id}` | 软删除 / 硬删（`?hard=1`） | |
| POST | `/api/changes/{change_id}/void` | 作废 | 对象 |
| POST | `/api/changes/{change_id}/restore` | 取消作废 / 取消归档（通用恢复） | 对象 |
| POST | `/api/changes/{change_id}/archive` | 单张归档 | 对象 |
| POST | `/api/changes/archives/project/{project_id}` | 整项目归档 | 对象 |
| GET | `/api/changes/archives` | 已归档列表（按项目/单张） | **裸数组** |

### 10.3 任务（`/api/changes/tasks`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/changes/{change_id}/tasks` | 新增任务（带 `parent_id` / `level`） |
| PATCH | `/api/changes/tasks/{task_id}` | 改任务（名 / 责任人 / 起止 / 是否完成） |
| POST | `/api/changes/tasks/{task_id}/toggle` | 勾选/取消勾选（**自动写 `done_at`**） |
| DELETE | `/api/changes/tasks/{task_id}` | 删任务（**有子项时级联删除全部下级**，前端二次确认并提示"将同时删除 N 个子项"） |
| POST | `/api/changes/{change_id}/tasks/batch` | 批量粘贴新增 |

**层级校验**：`level` 由后端按 `parent.level + 1` 推导，**超过 5 层直接 400**（中文提示"最多支持 5 层"）。

## 14. 验收清单（搭完逐条打勾）

**结构**
1. 一张变更单 = 一个物料；同物料同项目能建多张
2. 任务树能加到 **5 层**，第 6 层被拦（中文提示）
3. 子项能单独勾；子项全勾 → 父项自动已勾；点父项 = 批量全勾/取消

**时间与派生**
4. 只有叶子填起止；父项位置/长度/进度由子项自动汇总
5. 勾完成瞬间自动写 `done_at`，无需人工填
6. 超期未完成 = 红条 + 虚线拖到今日线；迟交完成 = 橙条 + 实际完成日竖标
7. 完成率、时间进度、偏差三者数值与手算一致（用 §5.4 的例子验）
8. 燃尽图计划阶梯线 + 实际线，只数叶子

**呈现**
9. 甘特图父条与汇总条为中性灰；红黄报警只出现在卡片/角标/色点
10. 项目卡片墙：按超期数降序、红边黄边、两种完成率、最紧急一行、类型拆分
11. 卡片墙搜索 + 分页可用（十几个项目场景）
12. 变更单列表行首色点正确
13. 折叠：任意层级可收；收起后父行保留汇总条 + 状态角标；**智能展开**只展开有问题的分支；**刷新后折叠状态仍在**

**预警**
14. 三处预警同源同数（顶部条 / 明细表 / Dashboard 卡 5）
15. 预警行必带责任人；无责任人标灰"未指派"
16. Dashboard 卡 5 = 方案乙；点击跳到变更页

**生命周期**
17. 任务全勾完 → 变更单自动"已完成"并记 `completed_at`
18. 手动提前完成 → 弹确认提示未勾数
19. 作废 → 默认隐藏、可从"已作废"筛出、可恢复
20. 删除 → 软删，列表不显示
21. 归档（整项目/单张）→ 只读；取消归档 → 恢复可编辑；**其他模块项目列表无任何变化**

**数据**
22. Excel 双 sheet 导入：按序号匹配、层级靠父项行号、错误行先列出
23. 导出 Excel 两个 sheet 内容完整
24. 空态统一整卡 `EmptyState`；筛选器支持 0/N 且保留入口
25. 枚举取值全部有兜底，不白屏

## 15. 与 v0.1 的差异（被推翻的建议）

| v0.1 的建议 | 定稿 | 原因 |
| --- | --- | --- |
| 界面只开放 2 层 | **支持多层，封顶 5 层** | 用户要求逐层手动添加 |
| 变更单号自动生成 `CHG-2026-0001` | **不要单号，用序号** | 用户明确不要 |
| 类型带"标准任务清单"（一键生成骨架） | **不做**，类型只是个名字 | 每种变更要交的东西不一样，用户自己加 |
| 进度按任务数量 / 人天加权 | **按时间自动算**（时间进度 vs 完成率的偏差） | 用户定调：管的是承诺兑现，不是百分比 |
| 记录"改期 N 次" | **不做** | 用户否掉 |
| 停滞预警（N 天无更新） | **不做** | 用户自己盯 |
| 变更单状态 5 态 + 审批 | **3 态，无审批** | 系统无登录无角色 |
| 父条随最差子项变红 | **父条保持中性灰**，报警交给卡片 | 用户口径：甘特图看结构，卡片看问题 |
| 变更完成后半自动回写主数据 | **推迟到二期**（且必须人工确认） | 一期先把本模块做扎实 |
| 只有一张甘特图（在详情内） | **两张**：详情单张 + 项目合并图 | 用户要老板看全局 |
| 预警阈值可页面配置 | 固定 3 天 | 已定，保持简单 |
