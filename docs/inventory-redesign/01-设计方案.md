## 1. 问题诊断

当前 `/inventory` 页面的结构是**单层全量大宽表**：

```
[标题栏]
[四卡：下单时机漏斗]        ← 口径错：讲的是"何时下单"，不是"库存还剩多少"
[筛选栏：项目/物料/供应商/基地 + Z + 过剩天数]
[图例 + 行数]
[大矩阵：每行 = 项目×基地×物料×供应商]
   └ 行内可展开 30 天 × 5 行矩阵（吃掉半屏）
```

三个具体病灶：

1. **口径错位**：四卡回答「什么时候要下单」（ROP 分桶），但业务第一眼要问的是「**我的库存还能撑几天**」（DOH）。DOH 是 ROP、建议补货、下单日的**共同上游**，理应占据首屏。
2. **无分层**：物料、项目一起堆在同一个表里，没有"项目 → 物料"的从属关系。项目数上去后筛选器本身就成了瓶颈，且**不选项目也全量渲染**，首屏就是几十上百行 × 30 列。
3. **行内展开毁掉对齐**：`GRID = 600px + 30×76px = 2880px`，展开后一行 5 层子行，与其它行完全不对齐，横向滚动 2880px 才能看到最右侧的产能校验（注释里也写了「不要 ml-auto，会推到屏外」——说明设计已经被宽度绑架）。

## 2. 目标结构（三级）

```
L0  项目选择层（默认落地）
    ├ 项目卡片墙：每卡 = 项目名 + 代码 + 计划行数 + DOH 四档角标 + 最紧急物料
    ├ 多选项目（勾选后进入 L1）
    └ 未选项目 = 不请求计划行（`enabled: false`）

L1  库存总览层（选定项目后）
    ├ 顶部四卡 = DOH 四档预警（口径见 §3）
    ├ 细分段条 = 下单时机（原漏斗，降级保留）
    ├ 工具栏 = 全局搜索 + 物料/供应商/基地多选 + 视图设置 + 导出
    ├ 主体 = 物料紧凑列表（一行一计划，**默认按 DOH 升序**）
    └ 点击行 → L2

L2  物料详情抽屉（右侧 Sheet，宽度 ~1100px）
    ├ 头部：物料名 + PN + 项目/基地/供应商 + 四档 DOH 大数字
    ├ 口径条：SS / 安全天数 / COV / ROP / 日均
    ├ 建议条：建议补货 / 最晚下单 / 预计耗尽 / 产能校验
    └ 30 天 × 5 层矩阵（原行内展开内容整体搬入，单元格仍可双击编辑）
```

### 2.1 为什么是「卡片墙 → 列表 → 抽屉」而不是继续单层

- **可扩展**：项目数增长只影响 L0 卡片墙（网格自适应）；物料数增长只影响 L1 列表（有排序+截断兜底）；单物料细节永远只占一个抽屉。三层各自独立增长，不会互相拖累。
- **对齐问题消失**：L1 列表不再需要 30 列，冻结列可以从 600px 收到 ~420px，描述性信息一行显示，横向滚动归零。
- **首屏即结论**：四卡 + 「按 DOH 升序」的列表 = 打开就看见"哪几个物料最危险"。

### 2.2 路由

保持单路由 `/inventory`，用 URL query 承载状态（可分享、可刷新保留）：

| query | 含义 |
|---|---|
| `?project=1,2` | 已选项目 ID（L0→L1 的门开关） |
| `?doh=stockout` | 四卡过滤（见 §3） |
| `?pn=&sup=&base=` | 物料/供应商/基地多选 |
| `?q=` | 全局搜索词 |

L2 抽屉用 `?plan=123`，支持直接分享某个物料的详情链接。

## 3. 顶部四卡（核心变更）

### 3.1 口径

**取「今日（窗口第 1 天）的动态 DOH」**，按四档分桶。DOH 定义沿用现有后端字段 `days[0].doh`（`doh_capped=true` 表示 30 天内未耗尽，按 30 处理）。

| 卡 | 判定 | 语义 | 色调 | 图标 |
|---|---|---|---|---|
| ① 库存耗尽 | `DOH ≤ 0` 或 `status === stockout` | 期末库存已归零，**已断货** | 深红 `#dc2626` | AlertOctagon |
| ② 紧急 | `0 < DOH < 安全天数` | 已跌破安全库存线，缓冲垫失效 | 红 `#ef4444` | AlertTriangle |
| ③ 偏低 | `安全天数 ≤ DOH < LT` | 剩余覆盖不足以走完一次采购周期 | 琥珀 `#f59e0b` | Clock4 |
| ④ 充足 | `DOH ≥ LT`（含 capped） | 覆盖完整采购周期 | 绿 `#10b981` | CheckCircle |

**边界规则（严格，必须与规则页一致）**：

- ① 优先于一切。
- ② `DOH < 安全天数`，**不含等号**（等号归 ③）。
- ③ `安全天数 ≤ DOH < LT`，**不含上界等号**。
- ④ `DOH ≥ LT`。
- **需求不可用三档（缺需求数据 / BOM 为 0 / 需求为 0）不入任何一档**，单列第 ⑤ 张灰卡「无法评估」，并显示计数与原因分布。这是硬约束：没数据的行绝不能因 DOH=30+ 被算进"充足"绿灯。

### 3.2 与旧口径的对照

| | 旧 | 新 |
|---|---|---|
| 主问题 | 何时需要下单 | **库存还能撑几天** |
| 基准 | ROP（= (LT+安全天数)×日均） | DOH（= 期末 ÷ 日均） |
| 分档 | 0 / D2-7 / D8-14 / D15-30 天 | 耗尽 / <安全 / <LT / ≥LT |
| 对"缺数据行" | 归入"窗口尾部"（会被误读为低风险） | **独立灰卡，绝不混入正常** |

### 3.3 四卡下方的「下单时机细条」（原漏斗，降级保留）

一条 ~28px 高的横向分段条，四段（今日 / D2-7 / D8-14 / D15-30），段内显示数量，点击过滤，再点取消。

- 段色沿用原橙/琥珀系，视觉重量远低于四卡。
- 段①右侧附小字提示：`其中 N 行下单也来不及`（沿用现有 `irreversibleToday` 计算，口径 = 今日 DOH < LT）。
- 标题文案：`下单时机（首次跌破 ROP 的日期分布）`。

### 3.4 四卡与细条的联动

两个过滤器**互斥**（同时只能生效一个），因为一个是 DOH 维度、一个是 ROP 维度，叠加会让用户困惑。切换时自动清空另一个，并在标题旁显示当前生效的过滤条件 chip + 「恢复全部」。

## 4. L0 项目卡片墙

- 网格：`grid-cols-1 sm:grid-cols-2 xl:grid-cols-3`。
- 每卡内容：
  - 首行：项目名（主） + `code`（次，mono 小字）
  - 第二行：`N 个推算单元 · M 个物料`
  - 第三行：**DOH 四档角标**（如 `🔴2 🟠3 🟢12`），灰卡"无法评估"仅在 >0 时出现
  - 第四行：最紧急物料 `物料名 PN · DOH 1.2天`
- 交互：卡片右上角 **checkbox**，勾选即加入 `?project=`；勾选 ≥1 个后卡片区折叠成一行 chip（`已选 2 个项目 [项目A ×] [项目B ×] [改选]`），同时 L1 列表出现。
- 「全选项目」按钮：一键选中全部（几十个计划量的场景下成本可接受）。

> **数据来源**：L0 需要各项目的 DOH 分布统计。为不破坏后端 `/plans` 的语义，新增轻量端点 `GET /api/inventory/project-overview`（见 `02-改动清单.md`），返回每个项目的 `{project_id, code, name, plan_count, material_count, doh_buckets:{stockout,urgent,low,ok,unknown}}`。**不传 project_ids 时也只返回统计，不返回任何物料明细。**

## 5. L1 库存总览层

### 5.1 工具栏

```
[🔍 全局搜索：物料名 / PN / 项目名 / 供应商]

项目: [已选 chip ×] [改选]   物料PN: [多选]   供应商: [多选]   基地: [多选]
                                        [视图设置 ⚙] [导出 ⬇] [刷新 ⟳]
```

- **全局搜索**（建议 A）：单输入框，同时匹配 物料名 / PN / 项目名 / 项目代码 / 供应商名，前端过滤，无需后端。
- **视图设置 ⚙**（建议 C）：抽屉/弹层，收纳 `服务水平 Z`、`过剩天数`、`列表密度（舒适/紧凑）`、`DOH 预警阈值（安全系数 1.25 是否启用）`。这三个参数不是每天改的，从主工具栏移走。
- **导出 ⬇**（建议 D）：导出**当前筛选后的列表**为 Excel（项目/基地/物料PN/物料名/供应商/LT/现有库存/日均/SS/安全天数/ROP/DOH/状态/建议补货/最晚下单/预计耗尽/产能状态）。新增后端 `GET /api/inventory/export`。
- **保存视图**（建议 B）：本轮**不做**，列入后续（见 `02-改动清单.md`）。理由：需要新增持久化表，与本次"改呈现"主题正交，避免范围失控。

### 5.2 列表布局（关键：彻底放弃 30 列）

冻结列宽从 600px → **420px**，右侧列改为普通横向列（不再是 30 天格），单屏可容：

| 列 | 宽 | 内容 |
|---|---|---|
| 物料 | 主+PN | 物料名（粗） + PN（mono 小字）+ 需求来源徽章 / 需求异常徽章 |
| 项目·基地 | 次行 | `项目名 · 基地名`（同一行内，小灰字） |
| 供应商 | 次行 | 供应商名 + code（小灰字） |
| LT | 56px | LeadTime（可编辑） |
| 库存 | 72px | on_hand（可编辑） |
| **DOH** | 96px | **今日 DOH，大字 + 色块**（本表核心列，视觉最重） |
| 状态 | 88px | InvStatus 徽章（断货/偏低/贴近安全/过剩/正常/无法评估） |
| 建议补货 | 96px | replenish_qty |
| 最晚下单 | 96px | order_by_date + 剩余天数 chip |
| 预计耗尽 | 96px | stockout_date |
| 趋势 | 88px | 30 天迷你 sparkline（DOH 走势，纯 SVG，无交互） |
| 产能 | 88px | 占用率迷你条 + 状态点 |
| → | 32px | 打开抽屉箭头 |

**行高**：舒适模式 ~52px，紧凑模式 ~40px。

**sparkline（趋势列）**：用 `days[].doh`（capped 记 30）画一条 30 点折线，背景按安全天数画一条虚线参考线。这是"一眼看出在恶化还是在好转"的最便宜手段（约 40 行 SVG 代码，无依赖）。

### 5.3 排序与截断

- 默认排序：**DOH 升序**（最危险在最上）；`doh_capped` 视为 30 排最后。
- 可点击表头切换排序：DOH / 建议补货 / LT / 最晚下单 / 物料名。
- 行数 > **50** 时只渲染前 50 行，底部一行「已显示 50 / N 行，[展开全部]」。几十行量级下通常不会触发。

### 5.4 筛选行为修正

- **未选项目 → L1 不渲染**（显示 L0 卡片墙）。技术上：`useInventoryPlans` 加 `enabled: projectIds.length > 0`。
- 级联规则保留：物料选项基于已选项目收敛；但**清空项目不清空物料选择**（避免用户改项目时丢失物料筛选）。

### 5.5 空态

- L0 无任何项目/计划 → 整卡 EmptyState：`尚无库存推算单元` + 「从底表建档」/「Excel 导入」两个入口。
- L1 筛选后 0 行 → 整卡 EmptyState + 明确原因（是四卡过滤还是筛选器）+ 「恢复全部」。（沿用现有规范：整卡统一，禁止"图空+表满"。）

## 6. L2 物料详情抽屉

右侧 Sheet，宽度 `min(1100px, 92vw)`，内容自上而下：

1. **头部**：`物料名 PN`｜`项目名 · 基地`｜`供应商名(code)`｜右侧四个 DOH 数字块（今日 DOH 大字 + 安全天数 + LT + ROP）。
2. **口径条**：SS / 安全天数（含"兜底"标）/ COV / ROP / 日均需求 —— 保留现有 `SafetyStockHint` / `RopTimingHint` 悬停图解。
3. **建议条**：建议补货 / 最晚下单（含"今天必须下单"chip）/ 预计耗尽 / 产能校验 —— 保留 `CapacityHint`。
4. **需求不可用提示**：BOM 为 0 / 缺需求数据 / 需求为 0 三种，按现有优先级显示，附**可点击跳转**到「供需管理」对应 `项目 × 物料`（建议 I）。
5. **30 天 × 5 层矩阵**：整段从原 `PlanBlock` 搬过来，`GRID` 改为 `LEFT_W(180) + 30×76`，横向滚动只在抽屉内发生。双击编辑逻辑**完全保留**（sys / md / mi / ending / doh 五层）。
6. **底部**：`删除档案`（危险操作，二次确认）+ `关闭`。

抽屉内矩阵宽 = 180 + 2280 = 2460px，抽屉 1100px，即横向滚动 ~1360px。虽然还要滚，但**滚动发生在一个独立面板里，不影响主列表对齐**，且抽屉可以拉到更宽。

> 备选（若你觉得 2460px 还是太宽）：矩阵改为**只显示 14 天**（宽 1244px，几乎不滚）+ 一个 14/30 切换。本轮先做 30 天，实测后再说。

## 7. 交互与视觉规范

- **可 discovers 的编辑**：现有"双击单元格"保留（老用户习惯），但每行 hover 时在 LT / 库存 / DOH 旁出现 **铅笔图标按钮**，点击即进入编辑。解决"双击不可发现"问题。
- **状态色不受主题影响**：`INV_STATUS_META` 等枚举取值继续 `?? 兜底`，本次新增的 DOH 四档同样加 `INV_DOH_BUCKET_META` 且全部带 fallback。
- **表格密度**：紧凑模式把 `py-2` → `py-1`、字号 `text-xs` → `text-[11px]`。
- **加载态**：L0 用卡片骨架，L1 用行骨架，不再整页 Skeleton。
