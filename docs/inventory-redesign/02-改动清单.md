## 一、后端

### 1.1 `backend/app/constants.py`（或库存常量所在处）[改]

新增 DOH 四档口径常量（与规则页 SOP 同源）：

```python
INV_DOH_BUCKET_STOCKOUT = "stockout"   # DOH <= 0
INV_DOH_BUCKET_URGENT   = "urgent"     # 0 < DOH < 安全天数
INV_DOH_BUCKET_LOW      = "low"        # 安全天数 <= DOH < LT
INV_DOH_BUCKET_OK       = "ok"         # DOH >= LT
INV_DOH_BUCKET_UNKNOWN  = "unknown"    # 需求不可用三档
```

判定函数放在 `inventory.py`，**唯一入口**：

```python
def _doh_bucket_of(out: InventoryPlanOut, lead_time: int) -> str:
    """今日 DOH 四档。需求不可用三档优先返回 unknown。"""
```

> 必须复用 `out.days[0]` 与 `out.safe_days`、`lead_time`，禁止另算 DOH。

### 1.2 `backend/app/routers/inventory.py` [改]

| 位置 | 改动 |
|---|---|
| 新增 `_doh_bucket_of()` | 四档判定，唯一入口 |
| 新增 `GET /project-overview` | 返回每项目 DOH 分布统计，**不含物料明细** |
| 新增 `GET /export` | 导出当前筛选结果为 xlsx |
| `list_plans` | **不改语义**；仅供 L1 使用（必须带 `project_ids`） |
| `inventory_summary` | 保留（遗留），不接 UI |

`GET /api/inventory/project-overview` 响应：

```json
[
  {
    "project_id": 1,
    "project_code": "P001",
    "project_name": "某项目",
    "plan_count": 12,
    "material_count": 8,
    "doh_buckets": { "stockout": 1, "urgent": 2, "low": 3, "ok": 5, "unknown": 1 },
    "most_urgent": { "material_name": "电容", "pn": "C-001", "doh": 1.2, "bucket": "urgent" }
  }
]
```

- 复用 `_load_plans` + `_out_of` → `_doh_bucket_of`，与 L1 完全同源。
- `most_urgent` = 该项目内 DOH 最小且非 unknown 的行；全为 unknown 时为 `null`。
- `material_count` 按 PN 去重。

`GET /api/inventory/export`：

- Query 同 `list_plans`（project_ids / base_ids / supplier_ids / pns / service_z / excess）+ `bucket`（可选，四卡过滤）。
- 返回 `xlsx`（`Content-Disposition: attachment`），列见设计文档 §5.1。
- 复用同一筛选与装配逻辑。

### 1.3 `backend/app/schemas.py` [改]

新增 `InventoryProjectOverview`、`InventoryMostUrgent` 两个模型。

## 三、规则页同步

`scripts/update_inventory_rules.py` [改]：新增/更新「顶部四卡 = DOH 四档」口径段落，**幂等**（标题未变的只 update，勿加入 legacy 删除列表）。

新增四条口径：

1. 四卡取今日 DOH，分档 耗尽 / <安全天数 / <LT / ≥LT。
2. 需求不可用三档（缺需求 / BOM=0 / 需求为 0）**单列「无法评估」，绝不入绿档**。
3. 下单时机漏斗降级为细分段条，口径不变（首次跌破 ROP 的日期分桶）。
4. L0 未选项目不加载计划行。
