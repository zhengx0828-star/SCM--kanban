Dashboard「项目/物料总数」怎么数
#0

Dashboard 首页顶部第一张卡片「项目/物料总数」的取值方法：

1. 项目数：和「供应商列表」页「项目」Tab 里显示的项目数量一致，有多少个项目就显示多少。
2. 物料数：和「供应商列表」页「物料」Tab 里显示的物料数量一致。物料以 PN 为准去重——同一个 PN 只算一种物料，有多少个不同的 PN 就有多少种物料。

这两组数字不用手动维护：在「供应商列表」里新增或删除项目、物料、供应关系后，Dashboard 会自动跟着更新，两边始终一致。

独供怎么判定
#0

同一物料下只有 1 家供应商即为独供（is_sole=true），自动推导，无需手动填写。独供意味着该物料供应完全依赖一家，为最高优先级风险。

QDC 评分五档
#1

Q（质量）/ D（交付）/ C（成本）评分为离散五档，仅允许：1（优秀）/ 0.7（良好）/ 0.5（合格）/ 0.3（不合格）/ 0（严重不合格）。不允许填五档之外的值。

权重方案怎么选（动态规则）
#2

同一物料下比较各供应商的 Q 评分：若 Q 一致 → 启用成本配比（Q20%·D10%·C70%）；若 Q 不一致 → 启用质量配比（Q70%·D10%·C20%）。理由：质量拉不开差距时以成本决胜负，质量有差异时质量优先。

加权分与计算配额怎么算
#3

加权分 = Q×wQ + D×wD + C×wC（w 按生效权重方案取）。计算配额 = 该供应商加权分 ÷ 同物料所有供应商加权分之和 × 100%。

建议配额怎么算
#4

下月建议配额 = 计算配额四舍五入取整（整数百分比）。同一物料各供应商四舍五入后合计可能出现 99% 或 101%，业务上可接受，不做补齐。

份额波动预警口径
#5

份额波动预警 = 本月系统份额相对上期份额变化 ≥ ±30%，即：本月份额 ≥ 上期×1.3（涨）或 ≤ 上期×0.7（跌）即触发预警。
例：某供应商上月份额 40%，本月升至 ≥52% 或跌至 ≤28%（±30% = ±12pt）触发预警。
边界：上期份额为 0 时，本月从无到有（>0）同样触发预警；无上月记录（首次录入/未结转）不判定。

建议偏差预警口径
#6

建议偏差预警 = |本月系统份额 − 上月建议配额| > 5 个百分点。含义：系统建议给的比例与实际执行的比例差异过大，说明配额建议未被有效执行。

多基地份额怎么算
#7

多基地时：本月系统份额 = Σ(基地份额 × 该基地拉线数量) ÷ Σ拉线数量（加权平均，权重=拉线数量）。份额在录入时逐基地填写：每条份额记录的 bases 自带 [{base, lines, share}]（1-4 个基地动态，不写死 A/B）。系统份额由公式自动计算：
- share 录百分比（0-100），也可用 0-1 小数（全部 ≤1 自动 ×100）；
- 某供应商不供某基地：该基地行保留但 share 留空（拉线仍计入分母，否则份额会被虚高）；
- 录入弹窗会聚合当月已有记录同基地的拉线数预填，请保持同基地拉线数一致（基地属性）。
手动改过份额（edited_manually）的记录不再被公式重算。

份额×评分四象限怎么看
#8

横轴 = 份额%，纵轴 = 加权分，每个点 = 一条供应关系，点大小 = 基地拉线数量，红点 = 独供。左上（份额低+评分高）= 潜力提升：评分不错但份额低，值得加量；右上（份额高+评分高）= 健康主力；左下（份额低+评分低）= 备选观察；右下（份额高+评分低）= 红色警报：最差的供应商拿最多活。

供需管理主表与 Supply Ratio 怎么用
#0

供需管理有两个页面：

· 项目列表页（/supply-demand）：列出所有项目，每张项目卡显示物料数/明细行数/供应商数；点击项目进入详情页。
· 项目详情页（/supply-demand/projects/:id）：该项目下的完整录入与视图，无下拉选择。
  - 客户需求（项目级 1-12 月）：单行 12 个月输入 + 年合计 + 保存
  - BOM 用量系数（每物料）：物料行 + 系数输入 + 保存
  - 供应商产能（每物料下每家供应商）：12 个月输入 + 年合计 + 保存
  - 物料需求（按 BOM 展开计算后的 1-12 月）：只读展示

概念：客户需求是项目级数据（客户给的是产品总需求）；物料需求 = 客户需求 × BOM 系数。同一物料多家供应商共享同一份客户需求与 BOM 系数（按物料级同步），但各供应商产能各自录入。

怎么录入数据：在项目详情页对应卡里改值后点「保存」即可。每张卡独立保存（改哪个保存哪个，互不影响）。

模块定位与数据来源（底表建造 / Excel 导入）
#0

库存信号塔 = 动态库存与补货风险监控看板：对未来 30 天库存做日度滚动推算，回答「什么时候库存有风险、什么时候必须下单、建议补多少」。
推算单元 = 项目 × 基地 × 物料PN × 供应商（唯一）。
建档两条路：① 从底表批量选取——底表已有「项目×物料×供应商」供应关系，勾选后指定基地与默认 LeadTime / 初始库存，档案与底表联动（物料需求 = 客户需求 × BOM 系数），底表一改推算自动跟随；② Excel 导入——适合一次性灌入历史数据。
Excel 列约定：项目代码 | 基地 | 物料PN | 供应商代码(可选) | 采购LeadTime(天) | 初始现有库存 | 历史需求_YYYY-MM（任意 N 列）| 未来预测_YYYY-MM（月度总量，按当月自然日摊日均）。
校验：LeadTime > 0、初始库存 ≥ 0；项目代码 / 物料PN / 基地 须已存在主数据（基地在「基地管理」维护）；未来预测月份必须覆盖「今天起 30 天」所在月，不足整行不导入；供应商代码留空时按「项目 × 物料」自动推断（优先主供）。
整表不含任何月份列 = 该批档案与底表联动。重新导入同一推算单元 = 更新系统数据并清空该单元全部手工修正（重建推算）。
数据只来自真实录入，页面不做演示数据；档案无任何需求序列时行内显式提示「缺需求数据」，不静默不亮灯。
**页面组织为三层**：L0 项目卡片墙（未选项目不加载任何物料明细）→ L1 库存总览（顶部今日 DOH 四卡 + 下单时机细分段条 + 物料列表）→ L2 物料详情抽屉（30 天 × 5 层矩阵）。详见第 7 条「页面结构与导航」。

需求、COV 与安全天数口径
#1

系统预测需求（日）= 未来预测月度总量 ÷ 当月自然日天数；窗口 = 今天起 30 天，每天自然滚动。
COV（需求变异系数）= 历史需求样本标准差 ÷ 均值，用于衡量客户需求是否稳定；样本不足 2 个月、或历史需求均值 ≤ 0（0 ÷ 0 不可算）时不计算，标签「不可算」，并回退兜底安全天数。
底表联动模式下，COV 只取「今天之前」的月份——底表存的是全年计划画像，未来月份属于计划而非历史，不能算进历史波动（该口径同步维护在规则页）。
波动标签：COV < 0.35 低 / [0.35, 0.8) 中 / ≥ 0.8 高。
安全天数 = 服务水平系数 Z × COV × √LeadTime（Z 与服务水平一一对应：90%→1.28、95%→1.65、97.5%→1.96、99%→2.33；页面顶部可整体切换服务水平，也支持直接填 Z）。COV 不可算时回退兜底安全天数（默认 5 天），行内标「兜底」。
安全库存 SS = 窗口日均需求 × 安全天数。
再订货点 ROP =（LeadTime + 安全天数）× 窗口日均需求。
每日期末库存 = 前日期末 + 当日手工修正入库 −（当日系统预测需求 + 当日手工修正需求）；首日前一天 = 初始现有库存。
动态 DOH = 从当日之后起，逐日扣减未来每日需求（计入未来手工修正入库），当日期末库存能完整覆盖的天数；不足一天按比例折算（0.1 天精度）；30 天内消耗不完记「30+」。
页面上「SS 安全库存 / 安全天数 / 历史 COV」带虚线下划线，鼠标移上去会弹出图解：本行历史需求柱状图 + 「安全天数 = Z × COV × √LT」「SS = 安全天数 × 日均需求」两条等式（数值全部取本行实际值）；点击可钉住不消失。

预警状态与颜色（每格颜色：判定优先级从高到低）
#2

深红（已断货）：期末库存 ≤ 0。
浅红（偏低）：期末库存 < 安全库存 SS，或 DOH < 安全天数。
黄（贴近安全线）：DOH 落在 [安全天数, 安全天数 × 1.25)。
蓝（过剩积压）：DOH > 过剩天数（默认 30 天，可调），或 30 天窗口内消耗不完。
正常：其余情况。
注意：这是「单元格颜色」的口径，与顶部四卡（今日 DOH 四档）是**两套独立口径**——颜色看「期末 vs SS / DOH vs 安全天数」，四卡看「今日 DOH vs 安全天数 / LeadTime」。同一行可能「颜色=正常、四卡=③偏低」，两者含义不同，不是矛盾。
需求数据不可用的行不产生任何风险色，也不进入四卡前四档，统一归「⑤ 无法评估」，详见第 8 条。

下单时机分桶口径（细分段条，非顶部四卡）
#3

本口径已从「顶部四卡」降级为四卡下方的细分段条（顶部四卡现为「今日 DOH 四档」，见第 8 条）。
分桶 = 每行「首次跌破再订货点 ROP」的日期落在哪个时段，一行只进一个桶：
① 今日需下单（D1）；② 7 天内需下单（D2–D7）；③ 8–14 天内需下单（D8–D14）；④ 15–30 天内需下单（D15–D30）。
段①的副标题额外提示「其中 N 行下单也来不及」——当日 DOH < LeadTime，即现在下单也赶不上断货前到货。
统计口径 = 表格行数（项目 × 基地 × 物料 × 供应商），只受项目/物料/供应商/基地筛选影响；30 天内不跌破 ROP 的行不计入任何段。
交互：点段 = 只看该时段的行，再点或「清除筛选」退出；与顶部 DOH 四卡互斥（同时只能生效一个）。

补货建议口径（建议补多少 / 最晚什么时候下单 / 什么时候耗尽）
#4

建议补货量 = 一个周期量，取 ROP 四舍五入（一个周期量 = LeadTime 内消耗量 + 安全库存）。
最晚下单日 = 30 天矩阵中「期末库存首次 ≤ ROP」的那一天；盘面同时给出剩余天数（0 = 今天必须下单，红色高亮）。该值是窗口下标，恒 ≥ 0，不存在「已逾期」语义。
预计耗尽日 = 30 天矩阵中「期末库存首次 ≤ 0」的那一天；30 天内不会耗尽则不显示日期。
若 30 天内始终未跌破 ROP：建议条显示「30 天内无需补货」。
三个数字随手工修正、LeadTime、服务水平实时重算。
图解：「再订货点 ROP」与「建议补货 / 最晚下单日 / 预计耗尽」都带虚线下划线，鼠标移上去弹出库存-时间图——把 ROP 线、安全库存带、最晚下单日、LT 等待期、到货日、预计耗尽日画在一起，并直接给结论「来不来得及」；点击可钉住。

产能校验口径（两层产能，只预警不拦截）
#5

两层产能：① 供应商在该物料上的总产能（供应商侧总盘子，跨项目共用）；② 分给本项目的月额度（在「供需管理 → 物料明细 → 供应商产能明细」按月录入）。
校验分母 = 该项目当月分配额度；分子 = 建议补货量（取最晚下单日所在月份的额度，额度与建议量必须同月对齐）。
占用率 = 建议补货量 ÷ 当月分配额度：≤ 70% 产能充足（绿）/ 70%~100% 产能紧张（琥珀）/ > 100% 产能不足（红）。
额度未录入时显式标「未录额度」，不做默认值、不误报。额度显式录入 0 视为真实为零——任何补货量都判「产能不足」，不与「未录额度」混同。
只预警不拦截：产能不足只提示风险，不阻止补货建议本身。
页面图解：建议条上的「产能校验」带虚线下划线，鼠标移上去弹出三层对比图——供应商总产能（集团盘子）／分给本项目（校验分母）／本次补货量（校验分子）用同一比例尺画长短，下配 0–70%–100% 阈值尺与结论，并写明「分母不是集团总产能」。点击可钉住，Esc 或点空白关闭。
待定：供应商总产能目前只在跨项目参考中展示，集团侧「各项目额度合计 > 总产能」的超分预警尚未实现。

全格可编辑与手工修正语义
#6

所有数据格都可编辑（无只读格）：
· 系统预测需求：双击改 = 覆盖该日摊日均；
· 手工修正需求 / 手工修正入库：双击直接改（可为负）；置 0 = 清除；
· 期末库存：双击直接改 = 覆盖自动算（盘点/实际差异），后续所有日基于覆盖值重算；
· DOH：双击输入目标天数 = 反推该日期末库存使 DOH 达标（等价设覆盖）；
· LeadTime / 初始库存：左列直接改（双击数字，或点 hover 出现的铅笔图标）。
任何修改立即重算整条链（含 ROP、补货建议、四档分档、下单时机分桶）。按业务要求，页面不显示手改标记（不用三角标/高亮区分），但覆盖值仍完整落库，重导该单元时一并清空。
入口位置：30 天矩阵已从「行内展开」移入「物料详情抽屉」——主列表保持零横向滚动，点击任意行打开右侧抽屉即可编辑全部日期格。

页面结构与导航（三层：项目 → 物料 → 详情）
#7

页面分三层，解决「物料与项目一多就堆成一张大表」的问题：

【L1 库存总览】选定项目后展示：顶部 DOH 四卡 → 下单时机细条 → 工具栏（全局搜索 + 物料/供应商/基地多选）→ 物料列表。

顶部四卡口径（今日 DOH 四档）
#8

四卡回答的是「**库存还能撑几天**」（旧版四卡回答的是「何时需要下单」，已降级为下方细条）。
口径：取「今日（窗口第 1 天）的动态 DOH」分四档，DOH = 当日期末库存 ÷ 窗口日均需求。
  ① 库存耗尽  DOH ≤ 0（或今日已断货）
  ② 紧急      DOH < 安全天数（严格小于，不含等号），**或 DOH < 3 天（绝对阈值）**
  ③ 偏低      安全天数 ≤ DOH < LeadTime（左闭右开）
  ④ 充足      DOH ≥ LeadTime
  ⑤ 无法评估  需求数据不可用
边界说明：DOH = 安全天数时归③（不含等号）；DOH = LeadTime 时归④。安全天数 > LeadTime 时②优先于③。
**为何②额外设「DOH < 3 天」绝对阈值**：安全天数 = Z × COV × √LT，当需求完全平稳时 COV = 0，安全天数退化为 0，判据 `DOH < 安全天数` 变成 `DOH < 0` 恒为假——DOH 只剩 1 天的行会被误判成③偏低。故叠加绝对阈值兜底（两套口径并行，谁先命中算谁）：只要 DOH < 3 天，无论安全天数多少，一律②紧急。阈值统一在 `INV_URGENT_DOH_THRESHOLD` 调整，改一处即四卡/列表/概览/导出全站生效。
**关键：「30+」（30 天内消耗不完）不得当作「充足」判据**——它只说明 30 天内耗不完；若 LeadTime > 30 天，DOH 30 天仍走不完一次采购周期，必须判③偏低。
点击任意卡片 = 只看该档的行（再点一次取消）。四卡与下方「下单时机细分段条」互斥，同时只能生效一个。
【无法评估】是独立灰卡，**绝不并入「充足」绿档**。三种成因分别计数并展示：缺需求数据（无历史/预测序列）、BOM 系数为 0（需求被乘成 0）、需求为 0（有序列但窗口日均 ≈ 0）。这三种情况下系统不产生任何绿灯，必须先把底层数据补齐才会参与预警；列表下方另有汇总条，可一键「只看这些行」集中补录。
