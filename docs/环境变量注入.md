# 容器环境变量注入清单

容器里只有 Python，数据库账号密码全部靠环境变量注入，**代码里没有任何硬编码凭据**。
变量名固定 —— `start.sh` 与 `backend/app/database.py` 只认这几个名字，改名不生效。

## 一、数据库连接（必填 3 项）

| 变量 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `SCM_MYSQL_HOST` | ✔ | — | 主机名或 IP |
| `SCM_MYSQL_USER` | ✔ | — | 用户名；OceanBase 可能要带租户（`user@tenant`） |
| `SCM_MYSQL_PASSWORD` | ✔ | — | 密码；内部自动 URL 编码，`@ # / ?` 不用手转义 |
| `SCM_MYSQL_PORT` | | `2883` | MySQL 是 3306；OceanBase 走 obproxy 是 2883 |
| `SCM_MYSQL_DB` | | `mtm-online` | 库名 |

整串 DSN（优先级最高，给了就忽略上面 5 项）：

```
SCM_DB_URL=mysql+pymysql://<user>:<password>@<host>:<port>/<db>?charset=utf8mb4
```

## 二、服务与兜底（可选）

| 变量 | 缺省 | 说明 |
| --- | --- | --- |
| `PORT` | `8000` | 监听端口 |
| `SCM_DB_FALLBACK_SQLITE` | `0` | 设 `1`：连不上库时退回本地 SQLite 继续启动（**排障用，正式别开**，否则数据会静默写进 SQLite） |
| `SCM_DATA_DIR` | `./data` | SQLite 目录（不配 MySQL 时才生效） |
| `SCM_DB_PATH` | `$SCM_DATA_DIR/products.db` | 直接指定 SQLite 文件 |
| `PYTHON` | 自动探测 | 强制指定解释器路径 |

## 三、三种写入方式

```bash
# 1) env-file（推荐：改完 docker restart 即可，不用重建镜像）
cp .env.example .env          # 只填 HOST / USER / PASSWORD 三行
docker run -d --name scm-kanban -p 8000:8000 --env-file .env scm-kanban

# 2) 逐个 -e
docker run -d -p 8000:8000 \
  -e SCM_MYSQL_HOST=<host> -e SCM_MYSQL_USER=<user> \
  -e SCM_MYSQL_PASSWORD='<pwd>' -e SCM_MYSQL_DB=mtm-online scm-kanban

# 3) docker compose：改 docker-compose.example.yml 的 environment 块
cp docker-compose.example.yml docker-compose.yml
docker compose up -d
```

## 四、启动日志怎么读

`sh start.sh` 第 3 步会打印实际读到的值（密码只显示位数，不打明文）：

```
[3/4] 数据库：MySQL/OceanBase  mysql://<user>@<host>:2883/mtm-online
      SCM_MYSQL_HOST=<host>
      SCM_MYSQL_PORT=2883（缺省 2883）
      SCM_MYSQL_USER=<user>
      SCM_MYSQL_DB=mtm-online（缺省 mtm-online）
      SCM_MYSQL_PASSWORD=***（12 个字符）
[1/4] 已连接  版本 OceanBase...  当前库 mtm-online  账号 ...  字符集 utf8mb4
```

| 现象 | 原因 |
| --- | --- |
| 显示 `<未设置>` | 变量没传进来（平台环境变量没生效 / 拼写错） |
| `***（0 个字符）` 或没有这一行 | 密码为空，或 `-e` 后忘了赋值 |
| `Access denied` | 用户或密码不对 → 试 `user` → `user@租户` → `user@租户#集群` |
| `Unknown database` | 库名不存在，或该账号看不到这个库 |
| `Can't connect` / `getaddrinfo failed` | 容器到该地址不通（内网/白名单），与账号无关 |
| 字符集不是 `utf8mb4` | 库的默认字符集不对，中文会乱码 |

连不上时只输出四行中文提示并以退出码 1 结束，**不会抛 uvicorn 堆栈**。

## 五、首次接库的顺序

```bash
# 1) 只验连接（不建表、不写数据）
python3 backend/init_mysql.py --check

# 2) 建表（19 张表 + 54 索引）
python3 backend/init_mysql.py --schema-only

# 3) 可选：把现有 SQLite 数据搬过去（目标表非空会跳过，不覆盖）
python3 backend/init_mysql.py --sqlite backend/products.db

# 4) 起服务
sh start.sh
```

`init_mysql.py` 默认读同一批环境变量，所以注入好之后直接跑，不用再传参数。

## 六、注意

1. 变量改了要**重启容器**才生效：`docker restart scm-kanban`。
2. 不要把真实密码写进 `Dockerfile` 或镜像层（`docker history` 能查出来）；只在运行期注入。
3. `SCM_DB_URL` 与 `SCM_MYSQL_*` 同时存在时，`SCM_DB_URL` 优先。
4. 密码含特殊字符建议用单引号包住，或改用 `SCM_DB_URL` 整串传。

## 七、密码含特殊字符（`@ # / ? : % +` 空格）怎么填

**一律用 5 个变量，不要用 `SCM_DB_URL`。**

`SCM_DB_URL` 是一整条 URL，密码里的 `@` 会被当成分隔符：`mysql+pymysql://u:p@ss@host/db`
解析出来的密码是 `p`，不是 `p@ss` —— 数据库回 `Access denied (1045)`，看起来像密码错，
其实是密码被截断了。程序现在会直接拦下这种写法并提示，不会静默截断。

| 写法 | 结果 |
| --- | --- |
| `SCM_MYSQL_PASSWORD='p@ss word#1/x?y'` | ✅ 逐字节原样传（已覆盖 `@ # / ? : % +` 空格、中文、引号） |
| `SCM_DB_URL=...u:p@ss@host...` | ❌ 被拦截：提示改用 5 个变量 |
| `SCM_DB_URL=...u:p%40ss@host...` | ✅ 可用（`@` 已编码为 `%40`） |

`SCM_MYSQL_*` 走的是 SQLAlchemy `URL.create()`，直接传原值、不做字符串拼接，所以不需要
你自己编码，也不需要加引号（.env 文件里的引号会被当成密码的一部分）。

写 `.env` 时的两个注意：

```ini
SCM_MYSQL_PASSWORD=p@ss word#1        # 空格、# 都可以直接写，行尾不要留空格
SCM_MYSQL_PASSWORD=p@ss$w0rd          # $ 会被 shell 展开时用单引号：'p@ss$w0rd'
```

`.env` 是 docker `--env-file` 读的，不做变量展开，`$` 按字面处理；只有 `export` 到 shell 时才需要单引号。

## 八、凭据中心的路径不是凭据

JDBC 配置里常见这种写法：

```
username: <namespace>:<app>:<user>
password: MTM_ONLINE_DATASOURCE_PASSWORD:<password>
```

左边是**凭据中心的路径**（`命名空间:应用:字段` / `配置项:值`），不是能直接登录的账号密码。
直接整串填进 `SCM_MYSQL_USER` / `SCM_MYSQL_PASSWORD`，OceanBase 会回 `1045 Access denied`。

| 变量 | 该填什么 | 不该填什么 |
| --- | --- | --- |
| `SCM_MYSQL_USER` | `<user>`（纯用户名，可带 `@租户`） | `<namespace>:<app>:<user>` |
| `SCM_MYSQL_PASSWORD` | 冒号后面那一段，如 `<password>` | `MTM_ONLINE_DATASOURCE_PASSWORD:<password>` |

判断方法：启动日志会打印密码的**字符数**。密码通常 8–20 位，40 多位基本就是整串路径被贴进来了。
程序现在也会主动告警：用户名含冒号、密码含 `_PASSWORD:` 前缀、密码长度 > 32。

`1045` 意味着 **TCP 已经连上、服务器到了认证这一步才拒**，网络和防火墙都没问题，
不要再查内网白名单，只调账号密码。

## 九、改完怎么生效（不用重建容器）

`start.sh` 启动时会读**同目录的 `.env`**：

```bash
docker exec -it scm-kanban sh -c 'vi /app/.env'   # 或直接在宿主机挂载的目录里改
docker restart scm-kanban
docker logs -f scm-kanban                          # 应看到 [0/4] 载入 /app/.env
```

优先级：**`docker run -e` / `--env-file` 注入的变量 > `/app/.env` 文件**。
即容器创建时已经注入的值会盖住文件里的同名项；想让文件生效，就得把 `--env-file` 去掉或改成对应值。

## 十、连不上时怎么一步定位

`backend/probe_login.py` 绕开 DSN 拼接，用 pymysql 直连，把候选组合挨个试：

```bash
python3 backend/probe_login.py --host <ob-host> --port 2883 \
    --users '<user>,<user>@<tenant>,<user>@<namespace>' \
    --passwords '<password>' --database mtm-online
```

输出直接告诉你哪一组能进，成功后会把该抄进 `.env` 的用户名打出来；密码只显示长度与前两位。

| 返回码 | 含义 | 该动哪里 |
| --- | --- | --- |
| `1045` | 认证被拒（网络是通的） | 用户名要不要带 `@租户`、密码是否真值 |
| `1049` | 登录成功但库不存在 | `SCM_MYSQL_DB` 写错，或该账号无此库权限 |
| `2003` | 连不上主机/端口 | 内网、白名单、端口 |
| `2059` | 认证插件不匹配 | 少见，需 DBA 调 `mysql_native_password` |

默认最多试 6 组（防账号锁定），要更多加 `--force`。
